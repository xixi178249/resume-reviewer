# v2.2.0（2026-11-04）

## 这一版在解决什么

v2.1 的改稿工作台是一个**独立页面**：用户得自己打开 `/chat`，再重新上传一遍简历。
评审报告里写满了「这条要改」，但报告和工作台之间没有门——看完报告想动手，得重新走一遍上传。

这一版就补这一扇门：**报告页多一个「在线改简历」，点进去的时候把刚出的报告一起带过去。**

## 新增

### 1. 报告页的入口（`web/index.html`）

报告底部操作区第一行是通栏主按钮「在线改简历」（`#goChat`）。点击时把三样东西塞进 `sessionStorage.rr.handoff`，然后跳 `/chat?from=review`：

| 带什么 | 为什么 |
|---|---|
| `session_id` | 同一份**已脱敏**正文，不再上传一次 |
| `review_id` | 刚出的那份报告——分数、verdict、问题清单原样搬过去 |
| `job` / `jd` | 改稿时模型要知道「按哪个岗改」 |

历史报告（没有会话了）会额外带 `text`（预览里的脱敏正文），所以从历史记录也能直接改。

存储位置只用 `sessionStorage`：和 API Key 一样，关标签页就没，不落盘、不写 cookie。

### 2. 交接是真的「同一份结果」，不是重评一次（`web/server.py`）

`POST /api/chat/start` 新增可选 `review_id`：命中就把它存成 v1 的评分，返回 `carried_review: true`，**不再跑后台基线评分**。

理由是口径：如果重评，同一份简历在报告页是 70 分、进工作台变 68 分，用户第一反应是「这系统自己都不一致」，而两次真实的差别只是采样抖动。带过去最省事也最诚实。

带不过来（报告被删、JSON 坏了、id 不合法）时**静默退回**原来的后台评分路径，不会因为一个可选参数把开台卡死。

### 3. 工作台接得住（`web/chat.html`）

- 页面加载读到 `?from=review` 就消耗交接包、直接开台；开台成功后把 URL 换成 `/chat?chat_id=…`，刷新是「接着改」而不是「重新开一条」。
- 没有 Key（用户是走「基础评测」看的报告）不弹窗，用横幅说明「改稿要调模型」；填完 Key 会自动接着开台。
- 正文栏标题显示 `v1 · 1296 字 · 70 分 · 目标岗：产品经理实习`，改的时候知道按哪个岗改。

## 顺手修掉的三个真 bug

1. **两个页面的 Key 格式不兼容**：评审页把 Key 存成 JSON `{key,baseUrl,model}`，工作台按纯文本读——从评审页跳过来，输入框里会出现一坨 JSON。现在两边都按 JSON 解析，纯文本也兼容。
2. **`?from=review` 缺正文时无限打扰**：没带过来会推一条警告，但刷新后还会再推一次。改成只在真的没交接包时提示一次，且措辞不再指向「上一页」。
3. **交接包被 key 检查挡在前面**：原来先查 Key 再消费交接包，用户没填 Key 时 `session_id` 没被记住，填完 Key 什么都不发生。现在先消费、再查 Key。

## 已知边界

- 版本链按**正文内容哈希**归一：同一份简历（哪怕换文件名）评过多次，会接在同一条时间线上，看到的是历史上所有版本，不是干净的一条。这是 v2.1 的既定设计，不是这一版引入的。
- 公网版是 `ephemeral`：进程重启后 `chat_id` 失效，交接包也随之过期。工作台会明确说「这个会话已经失效了」，不会假装还在。
