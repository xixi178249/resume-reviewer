# v2.4.1 · 写得太少的简历，不猜分数

## 改之前是什么样

粘贴一份只有 80 来字的草稿（学校 + 专业 + 一段社团），流程是：

```
只提取到 81 字，可能是空白页或扫描质量太差。请换一份文件，或直接粘贴文本。
```

或者过了这一关、真评了，就得到「55 分 · 待改」——用户拿着这个分数不知道该改哪儿，
因为它不是评出来的，是在五维里有两维没证据的情况下硬算出来的。

两种反应都是错的：**拒收**把「他缺的是证据」说成了「你的文件坏了」；
**给分**则把一个猜的数字包装成了结论。

## 现在分四档

| 字数（不含空白） | 判定 | 行为 |
| --- | --- | --- |
| 0 或占位符（`test`、`1111`、单字重复过半） | 垃圾 | 拒收，提示重新粘贴（`RESUME_TOO_THIN`，可重试） |
| < 40 | 太短 | 拒收，但错误信息说清「低于 40 字，补上学校/经历/技能任意两块」 |
| 40 ~ 120 | **建议模式** | 不评分、不给结论标签、不落盘，只给「缺什么 + 问三个问题 + 结构骨架」 |
| > 120 | 正常 | 走原来的五维评分 |

## 建议模式长什么样（真机输出，73 字草稿）

```markdown
# 先补信息，暂不评分（当前 73 字，不含空白）

> 不到 120 字时，五个维度里至少两维没有证据，算出来的分会是猜的——猜一个分数给你，
> 比不给更糟。所以这里**不评分**，只说清缺什么、先补哪几条。

## 现在缺的是
- **岗位对口**：没写想投什么岗位，五维里的「岗位对口」无从判断
- **结果与影响**：全篇没有一个数字：做了什么、做成什么样都读不出来
- **竞争力差异**：没有和同专业同学区分开的任何信息（竞赛/证书/项目/实习）

## 先回答这几个问题
1. 你这次想投什么岗位？写成一句话，例如「互联网 · 产品经理实习生」。
2. 你做过的事里哪一件有能写出来的结果？改前多少、改后多少、怎么统计的？
3. 同专业的同学大多有什么，你有什么是他们没有的？

## 按这个骨架补，够 120 字再评一次
（基本信息 / 教育 / 经历三段式 / 技能，见报告）
```

页面上的分数环**不出现**——环一出现就等于宣布「我评了」，哪怕里面写的是「—」。
卡片改成一行徽标「不足以评分」，外加缺口标签。

## 四条设计取舍

1. **不给 0 分，给「没评」**。0 分是一个结论（很差），没评是一个状态（信息不够）。
   两者在排序、历史、分差里含义完全不同，混用会污染版本链——所以建议模式
   **不写 `reports/`**、`review_id` 为空、下载按钮隐藏。
2. **120 是线，不是拍脑袋**。一段真实实习（岗位 + 动作 + 结果）最低 60~80 字，
   加教育与技能约 120；不到 120 时五维里至少两维缺证据，误差会盖过分数本身的差别。
3. **最多问 4 个问题**。问题多了用户不会答（等于没问），少了定位不准；所以按缺口
   选题，最多 4 条，且必须带一句可照抄的例子。
4. **不为注定打不准的分要 Key**。判断放在「用谁的模型」之前：正文本来就不够，
   先让用户填 key 再告诉他「其实没评」是最差顺序。

## 顺手做的两件事

- `docs/评分规则.md` 新增 §9.1「简历太短：不评分，先补信息」，三个阈值全部由
  `config/rubric.yaml` 的 `thin:` 段生成（改了配置不重新生成，`--check` 会报红）。
- 粘贴框提示从「至少 80 个字」改成「写不全也能贴：不到 120 字会给建议，不会硬塞分数」——
  旧文案本身就在劝退正好需要帮助的那批人。

## 数字

- 测试：26 个套件 / **542 条断言**（v2.4.0 是 25 / 517，本轮 +1 套件 +25 断言）。
- 新增 `scripts/test_thin_resume.py`（23 个测试）：阈值关系、四档边界（39/40/120/121）、
  建议模式不含 score/verdict、问题数与问句形态、报告不含分数泄漏、
  服务端不为草稿要 key、不为草稿写盘、121 字以上仍正常评分。

## 没做的

- 没有给建议模式做「估个大概分数（例如 40~55）」。区间估分仍然是猜，只是把猜藏进了区间。
- 没有让模型参与建议模式。它读不出「用户缺什么信息」——那是规则能判定的事，
  交给模型只会多一次不确定的输出。
- 没有把 40 字以下也做成建议模式。那时连「你做过什么」都无法判断，
  给的建议只能是通用模板，等于换了个说法的废话。
