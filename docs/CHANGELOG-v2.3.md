# v2.3.0（2026-11-05）

一次只做一件事：**让「目标行业」决定五个维度的权重**（D1）。评分口径本身（维度分怎么打、
每维 0~5 分怎么判）**一条没改** —— 改的只是「把五个维度合成一个总分」时谁更重要。

规则版本仍是 **v1.8**。

## 为什么加这个

同一份简历投互联网和投国企，该被看的点是不同的：国企更看学历、稳定性、资质；设计岗更看
作品集和排版；销售更看结果数字。以前我们只有一套 25/25/20/15/15，等于拿同一把尺子量所有
行业，用户会觉得「这分数跟我这个行业没关系」。

现在：**换行业 = 换一套权重 = 总分变，维度分不变。** 同一份简历实测：

| 行业 | 总分 | 五维分（未变） |
| --- | --- | --- |
| 通用（不选） | 62 | 4 / 4 / 4 / 1 / 1 |
| 互联网/科技 | 64 | 同上 |
| 金融/银行 | 62 | 同上 |
| 国企/体制内 | 60 | 同上 |
| 设计/创意 | 55 | 同上 |

（同一份「产品经理实习」简历，规则引擎评测。维度分四位数字完全一致，只有总分随权重变。）

## 具体做了什么

### 1. 权重档案写进唯一真源 `config/rubric.yaml`

新增 `industries:` 段，11 个档案，每个都有 `label`（中文名）、`emphasis`（一句话说明这个
行业最看重什么）、`weights`（五维百分比，合计 100）：

```
default 25/25/20/15/15（通用，兜底）
tech    25/28/20/12/15   互联网/科技
finance 30/18/22/15/15   金融/银行
soe     32/15/20/18/15   国企/体制内
design  22/18/18/27/15   设计/创意
product 25/28/20/12/15   产品/运营
education 30/22/18/15/15 教育/科研
medical 32/20/20/13/15   医疗/医药
game    25/26/22/12/15   游戏/娱乐
retail  25/30/18/12/15   销售/零售
gov     32/14/20/19/15   政府/公共事业
```

维度顺序固定为 `role_fit / impact / evidence_quality / structure / competitiveness`
（岗位对口 / 影响与结果 / 证据质量 / 结构与表达 / 竞争力信号）。**权重合计必须 100、维度名
必须与顶层 `weights` 完全一致**，不满足直接抛 `RubricError`，不会静默凑合。

行业键（yaml 的 key）必须是 ASCII —— 解析器只认 `[A-Za-z_][A-Za-z0-9_]*`，中文名放 `label`。

### 2. `scripts/rubric.py` 新增四个函数

- `weights_for(industry)`：`default`/空 → 读顶层 `weights`（保持与旧行为逐位一致）；
  其它键读 `industries.<key>.weights`，返回 0~1 的浮点。
- `weights()`：改成 `return weights_for(None)` —— **十几处老调用点一行都不用改**。
- `list_industries()`：`[(key, label, emphasis)]`，`default` 永远排第一（页面下拉第一项是它）。
- `industry_profile(key)`：给前端/报告用的字典。

**未知行业不静默回落**：`weights_for("不存在的行业")` 抛错，错误信息里列出可选键。
只有「用户没填」才走通用——「填了个错的」和「没填」是两件事，混起来就查不出配置写错了。

### 3. 打分/门禁/引擎全线接上

- `scripts/check_output.py`：新增 `weights_of(review)` / `industry_known(review)`。
  「分数是否自洽」的检查改用 `weights_of`，否则按行业算出来的总分会被自己的门禁判成不自洽。
  报告里写了未知行业 → 记一条 warning（「已按通用权重评分」），不当错误拦。
- `scripts/local_engine.py`：`review_text(..., industry="")`；`doc["industry"]` **只在选了行业时
  才写**，所以旧报告不会被凭空加上字段。
- `scripts/quality_gate.py`：重算总分时用 `weights_of(doc)`。
- `web/server.py`：`_review_config_hash(...)` 把 `industry` 也算进去 —— 换行业就是换了一把尺子，
  两次分数之差不能当「简历变好了」；`""` 与 `"default"` 视为同一把（不会出现假对比）。
  历史记录、`/api/review` 响应、`/api/chat/start` 的会话都带 `industry`，工作台重评沿用评审时
  那套权重（否则报告页 62 分、工作台重评 55 分，用户会以为系统自相矛盾）。

### 4. 契约层

- `prompts/output-schema-v1.8.json`：加 `industry`（enum 11 个键），**不在 required 里**。
- `prompts/system-v1.8.md`：输入段加 `- 目标行业：{{industry}}`，新增「# 行业权重」一节，
  里面是**从 rubric 生成的权重表** + 总分公式 + 两条硬话：「未给或不在表里一律用 default」、
  「**不允许因为行业不同就改动维度分本身**」。
- `scripts/run_eval.py`：`_industry_line()` 把权重直接摊在输入行上
  （`金融/银行（`finance`，权重 role_fit 30% / impact 18% / ...）`），模型没有算错的余地。

### 5. 页面

目标岗位下面多一个「目标行业」下拉（选项来自 `/api/health`，页面不写死行业名，加行业只改 yaml）。
报告顶部多一行：**「按 设计/创意 行业权重计算：作品集链接、审美与排版、工具链、项目类型跨度」**
—— 分数变了解释必须跟着变，藏在 tooltip 里等于没说。

## 防漂移

新增 `scripts/test_industries.py`（18 个测试），从四个层面钉住：

- 配置层：`default` 排第一、每档合计 100、维度名与顶层一致、label/emphasis 非空且唯一。
- 评分层：`weights_for("finance")["role_fit"] == 0.30`、`weights_for("design")["structure"] == 0.27`、
  `weights() == weights_for(None)`、未知行业抛错且消息里能看到可选值。
- 输出层：同一组维度分在通用=82 / 设计=78 / 金融≠通用；结构好但量化少的简历在 design 下比
  finance 下高（这才叫权重真的起作用）；`doc` 只在选了行业时才写 `industry`。
- 契约层：schema 的 enum 必须等于配置里的键集；`industry` 不在 required 里。

另外 `test_prompt_wiring.py` 用正则把 prompt 里的权重表**逐项**跟 yaml 对表，任何一边改了另一边
没跟上就红；`test_engine_choice.py` 补了两条：换行业必须换 config_hash、空行业等于 `default`。

测试总量：**24 个套件 / 478 条断言全绿**（v2.2.0 是 23 / 453，本次 +1 套件 +25 断言）。

## 没做的（写清楚，免得下次又讨论一遍）

- **没有「按行业改维度分」**。行业只影响加权，不影响单维打分标准。想改标准得动 rubric 的锚点，
  那是另一件事，而且会让「同一份简历换行业分数变」变成「标准也变了」，没法解释。
- **没有从 JD 自动猜行业**。猜错比不猜更糟：用户明确选了才算数，不选就是通用。
- 数据集、留出集、盲评这三样还是原来的状态（8/60、0/18、0/2 人），所以「准确率」仍然一个字都不能说。
