# 手动验收清单（自动化覆盖不到的部分）

> 自动化跑了两套：
> - `python scripts/qa_smoke.py --base http://127.0.0.1:8790 --mock`（53 项：编码/脱敏/PDF 分流/隐私同意/接口契约/错误文案/体积上限/导出/路径穿越/落盘/历史/review_id/删除）
> - `node _test/ui_check.mjs http://127.0.0.1:8765`（46 项：桌面 1280 + 手机 390，断言无横向溢出、按钮可命中、走通"粘贴→识别→评审→再来一份"、报告分数卡渲染）
>
> 下面这些**必须在真机/真人手里点**，脚本替不了。

## 1. 拖拽上传（AC-1.1）

1. 打开 `http://127.0.0.1:8765`；
2. 从资源管理器把一份 PDF **拖进虚线框**（不是点"选择文件"）；
3. 预期：出现「文件名 · X.XX MB」胶囊，按钮文案变「开始识别」。

> 自动化只能触发 `change` 事件，模拟不了真实拖拽的 `dragover/drop`。

## 2. 真·31MB 大文件（AC-1.2）

1. 找一个 >30MB 的 PDF（或把几张图拼成一个大 PDF）；
2. 拖进去点「开始识别」；
3. 预期：红色提示「文件太大（上限 30MB），压缩后再试」，页面不白屏、不卡死。

> 自动化用合成 base64 覆盖了 413 分支；真文件还要确认浏览器端上传不崩。

## 3. 直接双击 HTML（AC-5.2）

1. 在文件夹里双击 `web/index.html`；
2. 预期：顶部红条「你直接双击打开了 HTML 文件…请先启动服务」，并给出 `.\run_web.ps1`。

## 4. 服务没启动（AC-5.1）

1. 关掉 `start.bat` 的黑窗；
2. 刷新页面；
3. 预期：红条「连不上本地服务」+ 启动命令；点「下一步」也提示「本地服务已经停止」。

## 5. 评审中途打断（AC-5.3）

1. 上传简历，点「开始评审」；
2. 趁计时器在跑，去黑窗按 `Ctrl+C` 停服务；
3. 预期：红字「服务在线，但这次请求中途断了…直接再点一次」或「本地服务已经停止」，两者都算通过（取决于探活时机）。

## 6. MOCK 横幅（AC-5.4）

1. `.\run_web.ps1 -Mock`；
2. 预期：顶部黄底提示「当前是 MOCK 模式，评审结果是假数据」。

## 7. 剪贴板内容（AC-4.6）

1. 评审完成后点「复制报告」，粘到记事本；
2. 预期：是完整 Markdown，含 `# 简历评审 · 文件名`、结论行、三处改写；
3. 再点「复制可直接用的片段」，粘到 Word；
4. 预期：只包含事实无需确认、且不含 `[待补充：…]` 的改写，按原简历顺序；没有安全条目时该按钮不出现。

> 自动化只验证按钮给了「已复制」反馈，没核对剪贴板真实内容（无头浏览器权限不可靠）。

## 8. 下载的 .docx（AC-4.7 / AC-6.1）

1. 点「下载 .docx」，用 Word 打开；
2. 预期：标题层级、项目符号、等宽段落都在；中文字体是微软雅黑，不出现方块；
3. 点「下载 .md」，确认文件名是 `简历名.md` 而不是固定的「简历评审.md」。

## 9. 手机真机（PRD 2.5）

1. 手机和电脑连同一 Wi-Fi；
2. 电脑上 `.\run_web.ps1 -Port 8765`，手机访问 `http://<电脑内网IP>:8765`；
3. 依次点：上传 → 粘贴 → 开始评审 → 复制 → 下载；
4. 预期：不需要缩放就能点；按钮不重叠；报告能横向阅读不裁切。

> 无头 Chromium 只能证明 390px 布局不溢出，**代表不了 iOS Safari**（尤其是 `backdrop-filter` 和剪贴板权限）。

## 10. 扫描件 PDF 的 OCR 质量（AC-2.3 / AC-2.7）

1. 用手机拍一张简历 → 存成 PDF（或直接传 JPG）；
2. **先不勾选页面图授权上传一次**，预期提示需要明确允许，且不产生模型调用；
3. 勾选「允许在需要时发送页面图像」后再上传，看预览：
   - 识别出 1000 字以上且分得清小标题 → 通过；
   - 出现大量 `[无法辨认]` → 重新拍一张（光够、正对、别裁边）。
4. 到确认页不勾选「额外检查排版」，评审只使用文本；勾选后才允许再次发送页面图。

## 11. 会话过期（AC-3.11）

1. 上传简历后**等 31 分钟**再点「开始评审」；
2. 预期：「会话已过期，请重新上传简历」。

## 12. 多语言/双栈地址（AC-5.5）

1. `http://localhost:8765` 与 `http://127.0.0.1:8765` 都打开一次；
2. 预期：两个都正常（服务同时监听了 IPv4 与 IPv6）。

## 13. 隐私与删除（AC-2 / AC-6）

1. 打开页面确认没有「不上传云端」「只在这台电脑」等绝对化表述；
2. 文字型 PDF 默认不勾选页面图授权 → 识别后应显示「纯文本，未发送页面图」，确认页无排版勾选项；
3. 图片不勾选授权 → 提示需要允许页面图，页面不出现分数或报告；
4. 勾选历史条目右侧 `×` → 确认后 `.md/.json/.txt/.docx` 和分数记录一并消失。

## 14. 历史归属与异步（AC-6.8 ~ AC-6.13）

1. 用同一个文件名上传两份内容不同的简历，各评一次；
2. 预期：各生成一条历史记录，两份报告都存在，后者不覆盖前者；
3. 依次打开 A、B 历史，切到「简历预览」：每次只能看到对应那份的原文；删除 A 后 B 仍能打开；
4. 评审过程中点「换一份」或新建，等待旧请求返回：页面必须停在第一步，不出现旧报告或旧评分；
5. 同内容换岗位再评：不显示「比上次 +N」，出现“配置不同，不直接比较”的提示。

## 已知但暂不修的

| 现象 | 原因 | 影响 |
|---|---|---|
| 偶尔出现「分数不自洽：按维度加权应为 75，模型给出 72」 | 关掉思考后模型算加权和会飘 3~4 分，校验器按 ±2 判 | 报告底部会如实标出；分数仍按模型给的显示，不偷偷改 |
| 同一份简历两次评分差 1~5 分 | 模型非确定性 | 选「3 次取中位」可缓解 |
| 刷新页面要重新上传 | 会话是内存态（PRD 4.4 明确不做恢复） | 报告已落盘，改完直接看 `reports/*.md` |
