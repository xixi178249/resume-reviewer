# v2.1.0（2026-11-03）

## 这一版在解决什么

前五版都在回答「这份简历打得几分」。但用户真正要的是「**把它改好**」——而改稿这件事，直接让大模型「重写一遍」有三个死结：

1. **改哪了说不清**：模型回一篇新简历，人得自己逐字比对才知道动了哪句；
2. **改错了退不回**：一轮里 5 句改坏了 2 句，没有「只撤那 2 句」的机制；
3. **改完不知道变好还是变差**：分数是另一件事，不看就白改。

所以 v2.1 做的不是「聊天框」，是**补丁协议 + 版本快照 + 每次改完必重评**。聊天界面只是这套协议的入口。

## 新增能力

### 1. 补丁协议（`scripts/patch_protocol.py`）

模型不许自由作文，只许输出带锚点的结构化补丁：

```json
{"reply": "…", "patches": [{"id": "p1", "quote": "原文那一句（逐字）", "new_text": "改成什么",
  "why": "为什么", "fact_delta": "number_added|ownership_upgrade|scope_change|wording|none",
  "needs_user_confirm": true}]}
```

- **用引用定位，不用行号**：行号会漂，改了上一句下一句就错位。
- **`quote` 必须逐字存在**（弹空格/全角/零宽后仍能映射回原串），找不到就跳过，不猜。
- **分类由代码算，不采信模型自报**：抹掉排版字符后两串相同 → `layout`，否则 `content`。
  （模型很爱把「加了个空格」说成内容优化。）
- **编造数字在写入前拦**：`new_text` 里出现原文没有的数字 = hard，直接不进版本；
  权属升级（参与→主导）与删行 = soft，未确认也不进。
- 需要数据的地方必须写占位符（`«待补：指标»` 等四种写法），而不是编一个数。

### 2. 版本快照（`scripts/version_store.py`）

- 每次「采用补丁」存**整篇全文**为一个不可变版本，不做反向补丁计算
  （同句出现两次、用户中途手改、占位符被填过——反算的边界情况永远处理不完）。
- `parent` 串成线性链，**只允许基于最新版追加**，分叉直接报错（分叉之后「上一版」就没有意义了）。
- 撤回 = 切回 `parent`，不需要逆向计算；上限 10 版。
- `doc_id` = 正文 sha256 前 12 位：同一份简历换文件名也归同一条链。
- 评审结果单独存 `v{n}.review.json`，不塞进版本元信息。

### 3. 对话引擎（`scripts/chat_engine.py`）

- 上下文只带：简历全文 + 上一轮 issues（top 6）+ rubric 摘要 + 最近 3 轮 + 结构化摘要。
  **不带全量历史**——第 5 轮开始会又慢又贵还更不听话。
- 输出不是 JSON → `json_mode` + 把具体原因回灌重试一次；第二次仍失败返回
  `没听懂，换个说法（模型这次没按格式返回，什么都没改）`，**绝不静默降级成纯文本**。
- 采用后**立刻重评并显式报差**：`62 → 40（-22 分）` 并给「可以撤回」的建议；
  越改越差必须看见，不能只报「已更新」。
- 评分标准一律从 `config/rubric.yaml` 读，**不给 chat 单独一套逻辑**。

### 4. 命令行入口（`scripts/chat_cli.py`）

```powershell
python scripts/chat_cli.py --file samples/txt/05-产品经理-本科.txt --job 产品经理 `
  --message "把兼职那条改成有结果的写法，缺数据留占位符" --apply all
```

输出：建档 → 基线打分 → 补丁表（分类/事实变更/需确认/守卫提示） → 写入 v2 →
重评 → 对比 → 落实率 → 版本链。

## 实测（真模型 deepseek-flash，未填占位符）

```
[基线] v1 = 62 分（borderline）
[回复] 兼职板块三条 bullet 改为「动作+结果」结构，缺数据处留占位符
  [p1] 内容 / 加了数字 / 需确认
  [p2] 内容 / 加了数字 / 需确认
  [p3] 内容 / 加了数字 / 需确认
[写入] v2（基于 v1）— 已改 3 条（内容 3 条）
[重评] 40 分（reject）
[对比] 62 → 40（-22 分）
[建议] 这版比上一版低 22 分，可以撤回（撤销会回到 v1）。
```

**这个 −22 是真实结果，不是 bug**：三处占位符没填就送去重评，模型把
`«待补：统计周期»` 当成排版噪音扣了分。所以 CLI 现在会提示
「这版还有 N 个占位符没填……填完再评一次更准」。它同时证明了两件事：
① 改完必须重评，否则用户会以为 +12；② 报差比报喜有用。

## 测试

新增两个套件，`python scripts/run_tests.py` → **23 套件 453 断言全绿**：

- `chat-patch` 38 项：锚点定位（含空白归一化映射）、非法补丁丢弃、事实守卫三态、
  应用顺序、排版/内容分类
- `chat-version` 17 项：线性追加、分叉拒绝、上限、撤回、同正文复用链、路径穿越拒绝

## 已知边界

- 公网版留存是 `ephemeral`（v1.13 的设计）：版本链是临时态，页面会写明并提供
  「下载当前版本 .txt」。不要说「历史已保存」。
- 占位符必须人工填写。填完再评一次，分数才有意义。
- 桌面三栏 UI（左版本时间线 / 中简历 / 右对话流）尚未接入，目前入口是 CLI。
