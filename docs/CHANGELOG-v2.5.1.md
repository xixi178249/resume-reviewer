# v2.5.1：自评一轮，修掉 5 个只有走完整链路才会露出来的问题

> 这一版没有新功能。用户说"把做完的功能自己测评一遍"，于是写了 `scripts/selfcheck.py`（37 条端到端探针），
> 起真服务、发真请求、读真报告。结果：**569 条单元断言 + 55 条冒烟全绿的情况下，仍然抓出 5 个问题**。

## 一、新工具：`scripts/selfcheck.py`（37 条）

只做一件事：从用户视角走一遍，看功能之间会不会互相打脸。

```bash
python scripts/selfcheck.py                 # 自己起服务（mock），跑完关掉
python scripts/selfcheck.py --base URL      # 对已在跑的服务跑
python scripts/selfcheck.py --json out.json # 明细落文件
```

覆盖 14 个功能域 37 条：评审主链、分数可复算、行业权重、分数段与门槛、面试追问四件套、
低信息简历、ATS 平台层、规则公开页、可信度、隐私脱敏、版本链、改稿守卫、工作台缺 key、
边界与错误。**有 FAIL 退出码 1**，可以直接进 CI。

## 二、自评抓到的 5 个问题（已修）

| # | 问题 | 为什么测试没抓到 | 修法 |
|---|---|---|---|
| 1 | 报告 md 不写"按哪套权重算的" | 页面分数卡上有，单元测试只测了页面字段 | 报告头加 `> 计分口径：…`，五维权重与行业名从 `rubric` 现取 |
| 2 | 填了不认识的行业，静默按通用算 | `check_output` 只把警告放进了 `warnings`，没进响应 | 报告口径行说明「不在配置里，已按通用算」+ 接口 `warnings` 同步 |
| 3 | 报告不写这份文件能活多久 | 留存策略只写在网页上 | 报告头加 `> 保存方式：…`（`ephemeral` 说"重启即清空、当场下载"；`local` 说"留在 reports/、不上传"） |
| 4 | `qa_smoke.py` 在 Windows 控制台崩 | 用例名里带 `•`，GBK 编不出来 | 两个脚本入口都 `sys.stdout.reconfigure(encoding="utf-8")` |
| 5 | `package-lock.json` 版本漂移 | 一致性检查只在冒烟里，且一直红着没人看 | 对齐 2.5.0 |

第 1–3 条都是同一类毛病：**只在网页上说的话，用户一转发就丢了**。报告是唯一会脱离网站单独流传的东西，
口径、留存、可信度三件事现在都写在报告正文里。

## 四、自评结论（详见 `docs/自评-v2.5.md`）

- 功能完整度 **9.2 / 10**，可信度（分数准不准的证据强度）**6.5 / 10**。
- 两个数分开给是故意的：能跑 ≠ 算得准。
- 最该补的不是功能，是证据：金标 8 份 → 60 份、2 名独立标注者，才能把可信度抬上去。

## 五、没做的

1. **没有跑真模型链路**——走访客自己的 key，自评环境没有可用 key；上一次真跑是 v2.2 验收。
2. **没有做 ATS 与真实平台的对照**——规则仍是经验性的，"判不出就说判不出"能保证，"判得对"不能保证。
3. **没有动行业权重的区分度**——实测同一份简历 11 套权重只差 3 分；要改得保留一位小数或放大权重差，
   这会改变全部历史分数，得单独一个版本决策。
