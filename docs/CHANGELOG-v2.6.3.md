# v2.6.3：JD 关键词不再拿整句去比

> 一句话：中文 JD 的整句（「负责会员体系与用户增长」）和小标题（「岗位职责」）曾被当成关键词，
> 覆盖率被算成 20%，报告里印出「❌ 岗位职责：简历里完全没有」；现在按标点 → 并列词 → 削动词三层抽取。

## 改前长什么样

同一份简历（产品运营经理，695 字）+ 同一份 JD（182 字），报告里的「岗位匹配」一节：

```
**关键词覆盖 20%**：2 个在经历里有证据，8 个没有。

- ❌ **岗位职责**：简历里完全没有
- ❌ **负责会员体系与用户增长**：简历里完全没有
- ❌ **制定季度运营策略并对**：简历里完全没有
- ❌ **GMV**：简历里完全没有
- ✅ **负责**：简历原文命中
- ❌ **搭建用户分层与召回机制**：简历里完全没有
```

三个问题一次暴露：

1. 「岗位职责」是小标题，不是要求；
2. 「负责会员体系与用户增长」是一整句，简历当然不会原样出现；
3. 「制定季度运营策略并对」是被 12 字上限**截断**的残句；
4. 「负责」是动词，却被算成一条命中的关键词——**虚词命中还在给覆盖率注水**。

## 根因

`scripts/local_engine.py::_jd_match()` 只做了一件事：按标点切开，长度 2~12 字就收进词表。

```python
for raw in re.split(r"[。；;，,、\n\r/|（）()\s:：]+", jd):
    t = raw.strip(" -•·，,。.、")
    if 2 <= len(co.canon(t)) <= 12 and t not in terms:
        terms.append(t)
```

中文 JD 的主语、动词、宾语通常在同一句里，按标点切只会切出**分句**；英文 JD 按空格切能切出词，中文不行。

## 改法：三层削

新增 `_jd_terms()` 与 `_jd_term()`（`scripts/local_engine.py`）：

1. **按标点切句**（。；，、\n / | 括号 空白 冒号）；
2. **按并列词拆**（与 / 和 / 及 / 或）——「会员体系与用户增长」拆成两条；
3. **反复削动词与虚词**：开头动词（负责/熟练/掌握/具备/包含/包括…）、句中动词前缀（制定/搭建/提升/驱动…）、结尾连词（并对/并且/的/等/者）。

另加：

- 23 个停用词：岗位职责、任职要求、职位描述、加分项、福利待遇、薪资范围…；
- 纯动词过滤：`_VERB_WORDS` 里的词（负责/参与/熟悉…）不会单独成为关键词；
- 长度限制 2~8 字（原 2~12）。

## 改后

| | 改前 | 改后 |
| --- | --- | --- |
| 词表 | 岗位职责、负责会员体系与用户增长、制定季度运营策略并对、GMV、负责、搭建用户分层与召回机制… | 会员体系、用户增长、季度运营策略、GMV、用户分层、召回机制、留存、复购、产品、数据团队协作 |
| 覆盖率 | 20% | **50%** |
| 报告里的废提示 | 「❌ 岗位职责：简历里完全没有」 | 消失 |
| 纯动词注水 | 「✅ 负责」算命中 | 已过滤 |

同一份简历的总分：通用 64（勉强）、互联网科技 65（可投）——**分数口径没动**，动的只是「JD 里哪些词值得比对」。

## 测试

新增 2 条断言（`scripts/test_local_engine.py`）：

- `test_jd_terms_are_terms_not_clauses`：词表里不许出现「岗位职责」「任职要求」，不许含「并对」，长度 ≤8；必须出现「会员体系」「用户增长」「GMV」；「负责」不许进词表。
- `test_jd_coverage_on_chinese_prose`：整句 JD 也要能算出非零覆盖率，且词数 ≥3。

全量：**28 套件 / 588 条断言**（原 586）。

## 没做的

- 没做中文分词（jieba 之类）：项目至今零第三方依赖，为一个词表引依赖不值；三层削法在实测 JD 上够用。
- 没做同义词归并（「数据分析工具」vs「SQL」）：那是语义层的事，规则引擎不该假装能做。
- 没改评分口径：`config/rubric.yaml` 的权重、阈值、分数段一条没动。
