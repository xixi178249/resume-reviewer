# 人工准确度评测方案（阶段 D）

> 目标：回答“这个助手评得准不准、改得好不好”，而不是用 mock、单次样例或开发者自评冒充准确度。
>
> 当前状态：评测工具和数据契约已建好；**独立人工标注尚未采集**，因此项目暂不宣称任何准确率、MAE 或招聘预测能力。

## 1. 先明确能与不能验证的事

| 要验证 | 不能混淆成 |
|---|---|
| 模型分数是否与独立人工评分排序一致 | 模型分数是否等于“真实招聘结果” |
| 初筛/面试闸门是否与人工判断一致 | offer 通过率预测 |
| 每条问题是否原文支持、与岗位相关、严重性合理 | 引用“能搜到”即为正确 |
| 改写是否保持事实，并确实比原句更适合投递 | 文笔更漂亮 |
| 同输入重复评审是否稳定 | 用一次高分证明准确 |
| OCR 误差是否改变分数或建议 | OCR 字数看起来差不多 |

**不验证、不宣传**：offer 概率、录用概率、招聘通过率。

## 2. 角色与样本

### 2.1 人员

- **协调者**：本项目维护者，负责随机化、分发、收回、去标识化和跑评测脚本；不得充当独立标注者。
- **独立标注者 ≥2 人**：目标用户相近或具备实习招聘/技术面试经验；彼此不能看到对方标注，也不能看到模型分数和报告。
- **仲裁者 1 人**：只处理两名标注者不一致的维度和闸门；不参与首轮评分。

### 2.2 样本目标

- 试点：≥30 份；正式：≥60 份，建议 120 份。
- 分层至少覆盖：岗位（后端 / 前端或数据 / 产品 / 算法 / 其他）、简历强弱、文本 / 扫描件、有 JD / 无 JD。
- 当前 `samples/eval/dataset-v1.json` 只有 **8 份**，全部是 `development`，因为都参与过开发；**不伪造 heldout**。
- 新样本必须取得简历本人用于评测的许可；外部标注只在脱敏且获授权后进行。当前 `external_sharing=not_approved`，不得直接外发。

### 2.3 数据划分

- 先用约 70% 做 development，冻结 prompt/权重/阈值后再采集或解封约 30% heldout。
- 同一份简历的不同版本或同一来源，不跨 development/heldout。
- heldout 只能用于最终验收，不参与调参；每次查看都要记录。

## 3. 第一轮：独立盲评评分

标注者只看：

- 脱敏简历正文；
- 目标岗位和 JD；
- 评分量表与字段说明。

标注者**不得**看到：模型分数、档位、闸门、报告、few-shot、其他标注者结果。

### 3.1 评分维度

所有维度 1～5 分，必须按行为锚点打分：

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| role_fit 岗位匹配 | 基本不对口 | 部分技能/经历相关 | 经历直接对应岗位核心职责 |
| impact 结果与影响 | 只有职责描述 | 有结果但口径/归因不完整 | 动作、结果、规模可核验 |
| evidence_quality 证据质量 | 无法追问出真实贡献 | 有部分证据但链不完整 | 方法、边界、个人贡献都有证据 |
| structure 结构与可读性 | 找不到重点或严重排版问题 | 基本可读但层次一般 | 3 秒能抓到主线，排版稳定 |
| competitiveness 竞争力 | 明显低于同岗竞争者 | 达到门槛但无差异点 | 有稀缺证据/深度项目 |

总分不靠标注者另给一个 0～100 感觉分，而由固定权重计算：

```
总分 = round((role_fit×0.25 + impact×0.25 + evidence_quality×0.20
             + structure×0.15 + competitiveness×0.15) × 20)
```

闸门单独标注：

- `gate_hr`：15～30 秒初筛是否愿意留下；
- `gate_interview`：业务面试官是否认可经历。

### 3.2 标注文件

```powershell
python scripts/human_eval.py init `
  --dataset samples/eval/dataset-v1.json `
  --reviewer R01 `
  --out samples/eval/annotations/R01.json
```

要求：

- `reviewer_type=independent_human`；
- `blind_to_model=true`；
- `completed_at` 写实际完成日期；
- 每个样本的五个维度、verdict、两关、confidence 必填；
- `issues` 只写最关键的 0～5 条，`evidence` 从原文逐字摘录，最多 120 字；
- 不在标注文件里复制整份简历，不写手机号/邮箱等敏感信息；
- 任一样本没完成，不把半成品放进 `annotations/`。

> 为避免真实证据片段误提交，`.gitignore` 默认忽略 `annotations/*.json`、`audits/*.json`、`stability/`、`packets/`、`ocr-pairs.json`。确认去标识化后，再用 `git add -f` 有选择地纳入版本控制。

### 3.3 标注者一致性

工具计算：

- 每个维度的二次加权 Kappa；
- 总分 MAE；
- 总分 Spearman；
- 档位完全一致率。

一致性太低时先修量表和培训，不急着评价模型。参考解释：

- Kappa < 0.4：量表或培训有问题；
- 0.4～0.6：一般，需要仲裁；
- 0.6～0.8：较好；
- >0.8：很好。

这些是解释阈值，不是模型准确度门槛。

## 4. 第二轮：模型输出审阅

第一轮评分冻结后，再让标注者审阅模型输出；此轮允许看到报告，但需要做到：

- 不告诉标注者模型名、温度、repeat 次数和总分；
- 样本顺序随机；
- 每条意见独立判断：
  - `supported_by_source`：引用能否支持该判断；
  - `job_relevant`：是否与目标岗位有关；
  - `severity_appropriate`：严重性是否合理；
  - `actionable`：建议是否可执行。
- 每条改写独立判断：
  - `fact_preserved`：是否保持原文事实与限定条件；
  - `better_than_original`：是否确实更好；
  - `usable_as_is`：是否可以不改直接用。

模板：`samples/eval/templates/model-audit-template.json`，实际文件放 `samples/eval/audits/`。

注意：这一轮不是评分盲评。模型输出里必然出现模型自己的分数，不能把它和第一轮混在一起算“盲评一致性”。

## 5. 稳定性与 OCR

### 5.1 重复评审

- 先选 12～20 份分层样本，每份同配置重复至少 5 次；
- 文件命名：`samples/eval/stability/S01.run1.json`、`S01.run2.json`……
- 工具报告：分数均值/标准差/最大极差、档位翻转率、两关翻转率、意见 Jaccard。
- 不满足样本数时只报“探索性稳定性”，不推广。

### 5.2 OCR

- 人工校对一份扫描件原文作为 reference，再保存模型 OCR 结果；
- 在 `samples/eval/ocr-pairs.json` 中写路径或文本；
- 工具报告字符错误率（CER）和数字错误率；
- 必须同时记录数字错误是否导致分数/gate/建议改变。

## 6. 留出集与发布门槛

先看基线，再定具体数值门槛，不能为了让结果好看倒推阈值。建议硬门槛：

- 隐私泄漏：0；
- 核心事实编造：0；
- 不可交付结果被当成成功报告：0；
- 改写事实保持：接近 100%；任何事实升级必须确认或撤下；
- 留出集上报告分数 MAE、排序相关、闸门 precision/recall、改写可用率；
- 小样本必须同时报告 n 和 95% 区间，不写“准确率 95%”这类单点结论。

任一门槛未达到时，降低产品文案承诺或继续改进，不改展示口径来掩盖。

## 7. 一键生成报告

```powershell
python scripts/human_eval.py report `
  --dataset samples/eval/dataset-v1.json `
  --annotations samples/eval/annotations `
  --audits samples/eval/audits `
  --runs-dir samples/eval/stability `
  --ocr-pairs samples/eval/ocr-pairs.json `
  --legacy-gold samples/gold.json `
  --out reports/eval/human-eval-report.md `
  --json-out reports/eval/human-eval-report.json
```

退出码：

- `0`：达到预设数据规模和留出集要求，报告可标 `ready`；
- `1`：`not_ready`，只能作基线，不能声称准确度。

## 8. 现有基线怎么读

当前只有：

- 8 份样本，全部 development；
- 0 名独立标注者，0 份双人标注；
- 0 份模型意见/改写审阅；
- 0 组重复评审，0 组 OCR 对照；
- 4 份旧 `gold.json` 单人非盲评分，仅作探索性代理。

因此：

> **当前正确结论不是“MAE 8.0，所以准确”，而是“在 4 份非盲旧样本上，模型分与旧人工分的 MAE 为 8.0；这不能推出准确度，正式验证尚未开始”。**

后续每次补齐标注，重跑同一命令即可；报告会自动从未就绪转为可比指标，并保留样本量和限制。
