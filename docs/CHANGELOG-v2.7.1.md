# v2.7.1：把「卡在人身上」的那一步缩到最小

一句话：数据集从 8 份撑到 62 份（其中 54 份是**明确标注的合成样本**）、留出集从 0 变成 18 份，
于是切分护栏第一次在真实规模上跑通；`benchmark.py` 的阻断理由从「一团糊」收窄成两条硬约束，
其中一条现在只需要两个人各打 5 份分。

## 改前到底卡在哪

上一版自评的评测资产只有 5.0 分，`benchmark.py` 输出 `NOT_READY`，理由是四条：
数据集 8 < 60、heldout 0 < 18、独立标注者 0 < 2、已标注 0 < 60。

这四条混在一起，看起来像「什么都缺」，实际是两类事：

- **机械类**：规模不够、留出集为空 —— 这两条决定了 `dataset_build.py` 的去重、同组同侧、
  已标注样本冻结、`benchmark.py` 的留出集锁，**从来没在 60 份规模上跑过**；
- **人肉类**：两个人各打 5 份分 —— 这条只能等人。

混在一起最坏的结果是：等真攒到 60 份真实简历那天，才第一次发现切分、盲号、锁留出集
这些代码路径有 bug。

## 这次做了什么

**一、合成样本生成器 `scripts/make_synthetic_samples.py`（54 份，确定性可校验）**

八个岗位族 × 强/中/弱三档，同 seed 生成字节完全一致；每份正文第一行写死
`【合成样本，用于验证流水线，不是真实简历】`；`--check` 会逐份比对，手改或手塞文件都会报出来。

**二、provenance 一路带到底**

`dataset_build.scan()` 按目录名识别合成样本，写进样本的 `provenance: synthetic` 与
`data_sensitivity: synthetic_fixture`；`merge_into()` 的 `counts` 里 `real` 与 `synthetic` 分开计数。

**三、`benchmark.py` 不认合成标注**

`readiness()` 现在按真实简历单独设门槛：

```
· 真实简历 8 份 < 目标 60 份（另有 54 份合成样本只用于验证流水线，不计入）
· 独立标注者 0 人 < 2 人（双人盲评是硬要求）
· 真实简历里已标注 0 份 < 目标 60 份
· heldout 尚未做最终验收（未加 --allow-heldout）
```

「数据集 62 份 < 60」「heldout 18 < 18」这两条已经消失——它们本来就该消失，因为规模到了。
但**不是**因为合成样本让分数好看：给 54 份合成样本全编上标注，READY 依然是 False，
`real_annotated` 依然是 0。这条有测试钉着（`test_synthetic_annotations_never_count`）。

**四、pilot 包已经打好了**

`samples/eval/handouts/pilot-1/R01/` 与 `R02/` 各 5 份盲评稿 + 待填 json + 锚点卡（本地生成、不入库：稿子里是真实简历正文）。
人需要做的只剩：把两个目录发出去、收回两份 json、跑三条命令。**不用他们装任何东西。**

## 数字

| 项 | v2.7.0 | v2.7.1 |
|---|---|---|
| 数据集 | 8 份（heldout 0） | **62 份（heldout 18）** |
| 合成样本 | 0 | 54（全部带标记） |
| 测试套件 | 29 | **30** |
| 断言 | 620 | **641** |
| bench 阻断理由 | 5 条 | **4 条，全部是人或标签** |
| 自评总分 | 9.0（评测资产 5.0） | **8.4（评测资产 4.0）** |

## 顺手修掉的：自评器自己也想沾光

第一次跑评分卡时，`measure_evidence()` 把 `dataset-v2.json` 的 62 份全算成「金标」，
理由行写着「金标 62 份」。要是就这么发出去，等于**用生成器给自己发合格证**。

现在它按 `provenance` 分开数，并把话说全：

```
· 评测资产：真实金标 8 份、真实留出集 0 份（合成样本 54 份不计数）；
  bench=bench/report.json status=NOT_READY；局限清单=自评-v2.5.md
```

所以总分从 9.0 **降到 8.4**（评测资产 5.0 → 4.0，bench 从 PILOT 变 NOT_READY）。
这不是退步，是之前那 9.0 里有一分是「样本多」的错觉；现在这一维只认人给的分。

## 这次**没有**解决什么

- **真实简历仍是 8 份。** 合成样本证明不了量表准，只能证明流水线能跑。这一条只能等用户给材料。
- **标注者仍是 0 人。** 包打好了，人得自己找。
- **没有把合成样本写进 benchmark 的分母。** 这是刻意的：一旦写进去，`READY` 就变成了
  一个可以靠生成器刷出来的状态。
