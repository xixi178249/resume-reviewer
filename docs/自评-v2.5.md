## 三、功能之间有没有互相打脸

自评专门查"同一件事在两处说法不同"，这是最容易骗过单元测试的一类问题：

| 可能打架的地方 | 实测结果 |
|---|---|
| 页面分数 vs 下载的报告 | 一致（48 = 48），且报告现在写明计分口径 |
| 换行业：维度分变不变 | 不变，只有总分按权重重算 |
| 分数段 vs 结论 vs 门槛 | 48 分 → 不建议投 / HR 过 / 面试不过，三者自洽 |
| 低信息：给建议 vs 给分数 | 只给建议，`score=None`，历史里不留 0 分 |
| ATS 判不出 vs 说"没问题" | 判不出就写 `?`，不冒充 ✓ |
| 规则页门槛 vs 代码门槛 | 同一份 `rubric.yaml` 生成，逐字节比对 |
| 改稿：编造数字 vs 写得漂亮 | 守卫在**替换之前**拦，宁可少改一条 |

## 四、自评抓到的 5 个问题（全部已修）

这些是**测试全绿时仍然存在**的问题——只有从用户视角走一遍才会露出来。

1. **报告不写"按哪套权重算的"**（严重）
   页面上有「按 设计/创意 行业权重计算」，下载的 md 里一个字没有。报告是唯一会脱离网站单独流传的东西，别人拿到只看到 55 分，不知道口径。
   → 报告头加 `> 计分口径：设计/创意（design）权重：岗位对口 22% / … / 结构 27%；五维分本身不变`。

2. **填了不认识的行业，静默按通用算**（严重）
   用户以为"投金融"评过了，其实用的是通用权重，全程没人告诉他。
   → 报告口径行写明「你选的「X」不在配置里，已按通用算」，接口 `warnings` 同步给一条。

3. **报告不写这份文件能活多久**（中）
   网页上说 ephemeral，下载下来没有；转发给别人就成了来源不明的 md。
   → 报告头加 `> 保存方式：…`（`ephemeral` 说"重启即清空、请当场下载"，`local` 说"留在 reports/、不上传第三方"）。

4. **`qa_smoke.py` 在 Windows 控制台直接崩**（中）
   用例名里有 `•` → `UnicodeEncodeError: 'gbk' codec can't encode`，验收脚本自己先挂。
   → 入口 `sys.stdout.reconfigure(encoding="utf-8")`；`selfcheck.py` 同样处理。

5. **`package-lock.json` 版本漂移**（轻）
   `VERSION`/`package.json` 是 2.5.0，lock 还停在 2.2.0，冒烟里那条一致性检查一直在红。
   → 对齐 2.5.0。

修完后新增 7 条断言（`industries` 22 条、`retention` 11 条），总量 **562 → 569**。

## 五、测不到 / 测不了（诚实清单）

这一节比上面那几节更重要。**没测的就是没测，不写成"应该没问题"。**

| 项 | 为什么没测 | 影响 |
|---|---|---|
| 真模型链路（SSE 四阶段、apply 重评、delta） | 走访客自己的 key，自评环境没有可用 key | 上一次真跑是 v2.2 验收（68 → apply → 60，delta −8），之后**没有回归** |
| 分数准不准 | 金标 8 份，留出集 0/18，盲评 0/2 人 | `benchmark` 只能输出 `NOT_READY`；可信度条长期显示"未验证" |
| ATS 与真实平台 | 没有北森/Moka 的解析器做对照 | 规则是经验性的，只能保证"判不出就说判不出"，不能保证"判得对" |
| 移动端 | 只做了 CSS 断点，没真机 | 排版在手机上的实际表现未知 |
| 并发 / 压力 | 只验了限流文案与计数 | 多人同时评审的表现未知（单进程 + 全局锁） |
| 行业权重的区分度 | 实测同简历只差 3 分 | 见下 |

### 关于行业权重区分度（自己给自己挑刺）

同一份简历，11 套权重只算出 4 个不同总分（47 / 48 / 49 / 50）。原因很直白：**维度分是整数 1–5，权重差几个百分点，乘出来常常落在同一个整数上**。

- 好的一面：不会因为换个下拉框就"暴涨 10 分"，权重是微调不是魔法。
- 差的一面：用户主观上感觉不到差异，"投互联网 64、投国企 60"只在特定维度组合下出现。
- 可选修法（未做）：把总分保留一位小数，或把权重差异放大到 5 个百分点以上。**这两种都会改变所有历史分数**，得单独一次版本，不能顺手改。

## 六、结论

- **能交付**：37/37 端到端、569 断言、55 条冒烟全绿；核心承诺（分数可复算、编造数字拦在写入前、判不出就说不判出、低信息不硬给分）逐条实测成立。
- **最该补的不是功能，是证据**：金标从 8 份做到 60 份 + 2 名独立标注者，才能把"可信度 6.5"往上抬；在那之前，页面上的"未验证"不是保守，是准确。
- **下一步优先级**：① 金标与盲评（用户侧材料）→ ② 真模型链路回归 → ③ ATS 与真实平台对照 → ④ 行业区分度（需版本级决策）。
