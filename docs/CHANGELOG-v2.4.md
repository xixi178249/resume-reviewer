# v2.4.0：面试官会怎么追问，以及你该怎么答

> 规则版本仍为 v1.8（评分口径一条没改）。这一版只动一件事：把「面试追问」从
> **一串问题清单** 变成 **能照着准备的四条**。

## 一句话

原来报告只会说「面试官可能问你：这个数字怎么来的？基线是多少？为什么重要？」——
三个问号甩过来，用户还是不知道明天该准备什么。

现在每条追问都给全四件事：

| 字段 | 写什么 |
|---|---|
| `line` | 简历里那一行原文（逐字复制，可回查） |
| `ask` | 面试官会问的**那一句原话**（不是清单） |
| `prepare` | 要拿出来的东西：口径、基线、监控截图、分工边界；先说什么、再说什么 |
| `pitfall` | 答错长什么样——**说的是哪句话会被判定为没做过** |

`pitfall` 是这一版真正的增量：它能让人当场对上号。说中了，就是真风险；
说不中，这条可以划掉。写成「答不好会减分」等于没写。

## 报告里长什么样

```
## 面试官会怎么追问

> 下面第 1 条是高危：这一条答不上来，别的准备也白搭。

**1. 追问点**　`- 用 Go 实现限流与鉴权，压测 500 并发下错误率 0.1%`　（高危）

- 他会问：这个 0.1% 是怎么算出来的？分子分母分别是什么？
- 怎么准备：先报口径（哪个环节、什么条件下、改前改后各是多少），再给数据来源
  （压测报告、监控曲线、后台报表选一个），最后才说结论；分母算不清就把这条数字从简历里删掉。
- 答错的样子：答「大概是估的」「记不清了」，或者被问分母时改口说「这个是团队一起做的」。
```

## 四条设计取舍

1. **不新增字段就叫「升级」是假的**：所以 schema、prompt、规则引擎、报告渲染四层同时改，
   任何一层没跟上，`test_prompt_wiring.py` 会红。
2. **老报告不许因此打不开**：`questions[]` 仍然可读，`ask/prepare/pitfall` 不是必填。
   旧格式会得到一句提示（「这份结果是旧格式，重评一次会给出怎么答、答错长什么样」），
   但不会被拒收。
3. **高危必须给出路**：标了 `risk: high` 却不给 `prepare`，只在报警不给出路，
   自检会提示。这条是软提示不是硬拦——因为模型偶尔会漏，硬拦会让整份报告作废。
4. **规则引擎也照同一份契约产出**：不联网的那条路径同样给四件套，
   不让「用不了模型的人只能拿到半个功能」。

## 谁在防漂移

| 测试 | 防的是 |
|---|---|
| `test_prompt_wiring.py` 3f 组（5 条） | prompt 少了某个字段、示例 JSON 坏了、契约表还写着旧格式 |
| `test_local_engine.py`（4 条） | 规则引擎漏字段、`pitfall` 写成套话、兜底分支没有四件套、报告渲染没这一节 |
| `test_quality_gate.py`（3 条） | 新格式被误判成旧格式、旧格式被拒收、高危缺 prepare 无提示 |

断言数：505 → **517**（套件仍 25 个）。

## 没做的

- 没做「面试模拟对话」：那需要多轮交互与新的上下文存储，属于另一个功能，不该塞进报告。
- 没按岗位改追问套路（技术岗问口径、产品岗问取舍）：规则引擎做不到语义，写了也是假的。
- 没把 `pitfall` 做成可点击的「我答不上来」按钮：没有可靠的下一步可走，按钮只会变成摆设。
