## 二、v1.9/v1.10 的硬规则：谁的 key 谁付费，用不用模型由访客按按钮选

| 情况 | 发生什么 |
|---|---|
| 访客选「AI 深度评审」+ 填了自己的 key | 后端用它调模型，额度算他的；标准完全不变。可先点「验证 Key」几秒确认 key 可用 |
| 访客选「AI 深度评审」但没填 key | **直接拦住**（`LLM_NO_KEY`），不会悄悄降级成规则报告 |
| 访客选「基础评测」 | 走**本地规则引擎**（不调模型）：排版、结构、量化率、JD 覆盖、弱动词这些硬指标照样查，1~3 秒出报告；即使框里还留着 key 也不发请求 |
| 站长（你）的 key | **网页永远不会用它**。代码里那条路径已删除 |

所以 Render 上不配 `DSH_LLM_API_KEY` 是正常状态，不是漏配。

**换 key / 换模型 / 换接口地址，评价标准一个字都不变**：同一份 prompt（`prompts/system-v1.8.md`）、
同一套权重（`WEIGHTS`）、同一批通过线（`GATE_*`）。这条由
`scripts/test_engine_choice.py::RubricIdentityTest` 的 5 个断言守着，改坏了测试会红。
