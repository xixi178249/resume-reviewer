# 评分规则

> 本文件由 `scripts/gen_rules_doc.py` 从 `config/rubric.yaml` 自动生成，**不要手改**。
> 改了 yaml 请跑 `python scripts/gen_rules_doc.py`；忘了跑，`scripts/test_rules.py` 会报红。
>
> 给这份文档的理由：分数不该是黑盒。同一份简历，任何人对着下面的表，
> 都应该能算出同一个大致区间。算不出来，说明规则本身没写清。

## 1 总分怎么算

五个维度各打 1~5 分（整数），按所选行业的权重加权，再乘 20 换算成 100 分制：

```
overall_score = round(Σ(维度分 × 该行业权重) × 20)
```

不选行业时用 `default`（通用权重）。
**权重只改总分，不改维度分**——同一份简历换个行业，五个维度分不该变。

## 2 五个维度量什么（通用权重）

| 维度 | 量什么 | 权重 |
|---|---|---|
| `role_fit` | 岗位匹配度（经历是否对上 JD 的核心职责，而不是「专业名字像不像」） | 25% |
| `impact` | 结果与量化（是否说清结果、口径、归因，而不是只列做了什么） | 25% |
| `evidence_quality` | 证据质量（每条结论能否回指原文与原始出处，而不是自评） | 20% |
| `structure` | 结构与排版（分区、顺序、一页可读、机器可解析，而不是花哨） | 15% |
| `competitiveness` | 差异化竞争力（同岗人群里是否记得住，而不是堆砌荣誉） | 15% |

## 3 行业权重（选定行业后覆盖上表）

| 行业 | 权重顺序 | 这份简历重点看什么 |
|---|---|---|
| `default` 通用（不指定行业） | 25% / 25% / 20% / 15% / 15% | 五维通用标准，不看行业偏好 |
| `tech` 互联网/科技 | 25% / 28% / 20% / 12% / 15% | 项目影响力、技术关键词、GitHub、量化产出 |
| `finance` 金融/银行 | 30% / 18% / 22% / 15% / 15% | 学历与资质、证书（CFA/FRM/CPA）、合规意识、稳定性 |
| `soe` 国企/体制内 | 32% / 15% / 20% / 18% / 15% | 学历层次、专业对口、学生干部与党团经历、稳定性 |
| `design` 设计/创意 | 22% / 18% / 18% / 27% / 15% | 作品集链接、审美与排版、工具链、项目类型跨度 |
| `product` 产品/运营 | 25% / 28% / 20% / 12% / 15% | 数据驱动（DAU/留存/GMV）、从 0 到 1、方法论 |
| `education` 教育/培训 | 30% / 22% / 18% / 15% / 15% | 学历与教师资格、教学成果数据、课程研发 |
| `medical` 医疗/医药 | 32% / 20% / 20% / 13% / 15% | 学历与执业资格、规培与论文、临床或科研数据 |
| `game` 游戏 | 25% / 26% / 22% / 12% / 15% | 上线项目、引擎熟练度、品类理解 |
| `retail` 零售/电商 | 25% / 30% / 18% / 12% / 15% | GMV/SKU/转化率等运营数据、平台规则、活动策划 |
| `gov` 政府/非营利 | 32% / 14% / 20% / 19% / 15% | 公文写作、政策理解、基层服务、组织协调 |

权重顺序对应：`role_fit` / `impact` / `evidence_quality` / `structure` / `competitiveness`。

## 4 结论阈值

| 分数 | verdict |
|---|---|
| 80~100 | `strong_pass`（强推） |
| 65~79 | `pass`（可投） |
| 50~64 | `borderline`（勉强） |
| 0~49 | `reject`（不建议投） |

`verdict` 必须与分数严格一致，代码会校验；不一致的输出直接被判为不合格。

## 5 分数段（先定段，再在段内定分）

| 分数段 | 区间 | 典型画像 | 建议分 |
|---|---|---|---|
| `top` 强推 | 90~100 | 有 2~3 条带口径的结果指标（说清了基线与怎么算的）｜主线清晰，亮点能经得起三层追问 | 93 |
| `strong` 可投 | 80~89 | 关键经历有数字但口径不全（如只有「提升 20%」没说从多少到多少）｜分区完整、无自评词 | 84 |
| `pass` 可投（有短板） | 65~79 | 有结果但无数字，或数字只有工作量（「整理 300 条反馈」）｜弱动词行 ≤2 处 | 72 |
| `borderline` 勉强 | 50~64 | 分区不全或弱动词满篇｜引用里找不到一条能证明能力的原始证据 | 57 |
| `reject` 不建议投 | 0~49 | 技能与 JD 无关｜无一处分区｜无法从文字里提取联系方式 | 41 |

每段「长什么样」「最常见误判」写在 prompt 的分数段表里；这里只放区间与典型画像。

## 6 两道门（结论是算出来的，不许模型自由填）

| 门 | 条件 | 不过会怎样 |
|---|---|---|
| HR 初筛 | `role_fit` ≥ 3 且 `impact` ≥ 2 | 报告标「HR 初筛不过」，不再往下推荐 |
| 面试官视角 | `evidence_quality` ≥ 3 且 `high_risk` ≤ 1 | 报告标「面试官会追问到卡壳」，并列出高危项 |

## 7 内容层的硬性数字

| 项 | 阈值 | 为什么是这个数 |
|---|---|---|
| 一页字数 | 900 字 | 中文简历一页（含项目/实习）实测 800~1100 字 |
| 长句 | 单句 > 60 字 | 合格 bullet 多在 40~60 字，超过 60 就要拆 |
| 弱动词行 | 动词后实字 ≥ 4 | 防「完成」两个字被当成一行经历（v1.10 误报源） |
| 引用长度 | 6~200 字 | 太短无法回指原文；太长像复述、会绕过校验 |

## 8 输出契约

改写建议 2~6 条：少于 2 条像是「只有唯一解」，多于 6 条一页读不完。

## 9 改版对比、输入识别、评测门槛

| 项 | 值 | 说明 |
|---|---|---|
| 同版本判定 | 相似度 ≥ 0.62 | 同版不同稿实测 0.72~0.95，不相干简历 0.1~0.45，取中间 |
| 历史版本上限 | 40 份 | 每次都要读原文，不能无限翻 |
| 差异行上限 | 200 行 | 前端渲染上限，统计数字仍保留真实值 |
| 扫描件判定 | 抽出文本 < 120 字 | 低于此值走视觉转写，不硬猜 |
| 人工对齐门槛 | MAE ≤ 8 | 用独立标注数据测，不继承旧代理值 |
| 抖动控制 | repeat=3 极差 ≤ 6 | 同一份重复评三次 |
| 双人一致性 | Cohen's κ ≥ 0.6 | 四档 verdict |
| 仲裁触发 | 两名标注者差 > 15 分 | 差太多就进仲裁队列 |
| 闭环落实率门槛 | 可判定改写 ≥ 10 条 | 少于 10 条时 ±1 条≈10 个点，不给百分比 |
| pilot 门槛 | 5 份 × 2 人 | pilot 只验「两人是否用同一把尺」，不回答模型准不准 |

### 9.1 简历太短：不评分，先补信息

字太少时不打分，是因为五个维度里至少两维没有证据——这时给出的分数是猜的，比不给更糟。

| 字数（去空白） | 处理 | 说明 |
| --- | --- | --- |
| 少于 40 字 | 拒收，提示重新粘贴 | 占位符、乱码、只有一行标题：看不出是简历 |
| 40~120 字 | 建议模式：**不评分** | 指出缺哪几维的证据、先回答哪几个问题、按什么骨架补 |
| 多于 120 字 | 正常评分 | 五档分数段见第 5 节 |

建议模式最多问 4 个问题：超过这个数用户不会答，等于没问。报告里必须写明「不评分」及其原因，**不许把「没评」写成 0 分**。

## 9.2 平台层（ATS）：同一份简历，不同平台读法不一样

| 平台 | 它怎么看 | 检查项 |
|---|---|---|
| `beisen` 北森（校招/国企主流） | 先解析成字段再人工筛，段落缺起止年月会被并成一段 | 4 条 |
| `moka` Moka（互联网/中型公司主流） | 强依赖标准章节名分组，自定义标题会掉进「其他」 | 4 条 |
| `zhaopin` 智联招聘 | 平台内是表单字段，上传附件只作补充，筛选看表单 | 3 条 |
| `job51` 前程无忧 | 以关键词检索为主，附件解析容错低 | 3 条 |
| `shixiseng` 实习僧 / 牛客 | 学生简历为主，附件 PDF 直接看，关键词命中影响推荐 | 3 条 |
| `liepin` 猎聘 | 中高端岗位为主，经历连续性看得比关键词重 | 3 条 |
| `workday` Workday / Greenhouse（海外投递） | 强结构化录入：日期格式、单栏、无页眉页脚 | 4 条 |

- **北森（校招/国企主流）**：每段经历都写起止年月（2024.09—2025.06），别只写「2024」；用「教育经历 / 实习经历 / 项目经历 / 技能」四个标准标题；手机和邮箱写在正文第一屏，别塞进页眉或图片；单栏排版，不用表格分栏
- **Moka（互联网/中型公司主流）**：段落标题用标准名，「我的经历」「关于我」会被归到其他；起止年月完整，缺了整段可能识别不出；岗位关键词写进正文，别只写在「自我评价」里；单栏排版
- **智联招聘**：平台内表单逐项单独填满，别只传附件；表单与附件写一致（时间/公司名/岗位名差一个字就对不上）；岗位关键词在正文与表单里都出现
- **前程无忧**：岗位关键词出现在正文，别指望系统认同义词；手机和邮箱在正文里可直接复制；单栏，避开表格与文本框
- **实习僧 / 牛客**：一页以内（学生简历超过一页，前两屏就被刷完）；技能用岗位词写（「SQL」不写「数据库语言」）；教育、实习、项目、技能四块齐全
- **猎聘**：起止年月连续，空档要有交代；标准章节标题；岗位关键词与职级词（实习/校招）写清
- **Workday / Greenhouse（海外投递）**：日期写成 MM/YYYY（09/2024），别写「2024年9月」；单栏，无页眉页脚，无星级/评分条；文件名用英文，不用中文和空格（Li_Lei_Resume.pdf）；联系方式在正文首屏

平台层只回答「去检查什么」，**不回答「会不会被淘汰」**：这些是公开信息与实测经验的总结，不是任何平台的官方文档，规则也会变。正文里判不出来的（版面、平台表单、文件名）一律标 `unknown`，既不算通过，也不算不合格。

## 10 什么不算分

- 长相、性别、年龄、婚育、籍贯、政治面貌、民族、照片、健康状况：不评、不提、不进报告。
- 学校名气、公司名气、家庭背景：不作为竞争力加分（只作为事实陈述）。
- 与目标岗位无关的兴趣、证书堆砌：最多算「结构与可读性」的一处噪音，不加分。
