# v1.7.0（2026-10-25）

> 首个把“能跑”推进到“能交付、隐私表述真实、历史不串单、准确度有验证路径”的发布版本。
>
> 规则版本：**v1.7**
> 产品/包版本：**1.7.0**
> 提示词与输出契约：`prompts/system-v1.7.md`、`prompts/output-schema-v1.7.json`

---

## 1. 交付质量门禁

- 新增 `scripts/quality_gate.py`，把校验结果分为 `blocker` 与 `warning`。
- 总分按五个维度权重重新计算；分数与结论不一致时由代码修正，避免“模型自报 80 分但加权只有 65”。
- 编造数字、假引用、权属升级等问题改写逐条撤下；坏改写不会进入一键盘复制区。
- 没有合格候选时整份不交付：不展示分数、不给复制/下载、不写正常历史。
- 页面失败态只显示原因和重试，避免把失败候选伪装成报告。

## 2. 隐私真实性

- 文字型 PDF、DOCX、txt 默认只发送脱敏文本，**不渲染页面图**。
- 扫描件与图片必须由用户勾选“允许在需要时发送页面图像”后才调用视觉模型；未同意直接拒绝。
- 即使页面图已用于 OCR，评审阶段仍需单独勾选“额外检查排版”，才会再次发送。
- 服务端同时校验授权标志与图片存在，前端误传 `visual=true` 不会绕过。
- 上传临时目录在成功、业务拒绝、解析异常时都会清理；会话过期清空文本与页面字节。
- 历史支持逐份删除，真正删除 `.md/.json/.txt/.docx` 与分数记录。
- 移除“不上传云端”“数据不出本机”等错误承诺，明确文本、岗位、JD 会发给所配置的模型。
- 明确页面图当前**不做像素级脱敏**，可能包含姓名、照片、联系方式。

## 3. 历史归属与异步隔离

- 每份评审生成唯一 `review_id`、内容哈希与配置哈希。
- 报告文件改为 `{文件名}-{review_id前12位}.{md|json|docx|txt}`，同名简历不再互相覆盖。
- 历史列表、报告、预览、下载、删除全部按 `review_id` 关联。
- 历史没有原文时显示明确空态，不会把上一份简历的预览串过来。
- 原文超过 600 字可展开全文；历史抽屉在桌面与手机都可用。
- `.history.json` 升级为 v2 格式，原子写入；旧 v1 历史以 `legacy-*` 兼容，只保留每个名字最新一份。
- “比上次 +N”只在内容、岗位、JD、模型、图片设置与评审次数全部一致时计算；否则显示不可比。
- 前端使用请求令牌 + `AbortController`，换一份/打开历史/取消后，旧请求不会覆盖新界面。
- “再来一份”完整重置简历、文本、岗位、JD、次数、模式、预览与报告。

## 4. 人工准确度验证工具链

- 新增 `samples/eval/dataset-v1.json`，当前 8 份样本全部为 `development`。
- 新增双人盲评量表、标注 Schema、模型意见/改写审阅模板、标注者说明。
- 新增 `scripts/human_eval.py`：
  - 数据就绪度与开发/留出泄漏检查；
  - 二次加权 Kappa、总分 MAE、Spearman、档位一致率；
  - 模型 MAE/RMSE/排序一致率、闸门 precision/recall、bootstrap 区间；
  - 意见与改写审阅率；
  - 重复评审稳定性、档位/闸门翻转率、意见 Jaccard；
  - OCR 字符错误率与数字错误率。
- 当前状态严格为 **not_ready**：

```text
样本：8 / 60
独立标注者：0 / 2
双人标注：0 / 60
heldout：0 / 18
```

- 旧 `samples/gold.json` 的 4 份单人非盲标注只作探索性代理，**不构成准确度结论**。

## 5. 版本与接口

- 新增根目录 `VERSION`（`1.7.0`），作为服务端版本来源。
- `package.json` / `package-lock.json` 同步为 `1.7.0`。
- `GET /api/health` 新增 `version` 字段；`Server` 响应头为 `ResumeReview/1.7.0`。

## 7. 已知限制

- 权重的 25/25/20/15/15 仍为经验值，未做人工数据回归校准。
- 单次评审分数仍会抖动，3 次取中位只能缓解。
- 独立人工验证尚未开始；在标注数据达到门槛前，不得对外宣称准确率。
- 图像只做“是否发送”的授权控制，不做图像内容脱敏。
- 旧版历史只展示每个名字最新一份摘要；CLI 仍按源文件名写报告，不进入网页历史。
- Cloudflare 等临时磁盘实例重建后，本地历史会清空；长期历史需挂载持久卷或对象存储。

## 8. 升级说明

- 旧环境变量无需修改。
- 旧历史会在首次写入时转为 v2；旧报告文件保留，不会删除。
- 由于报告文件名带 `review_id`，不要再依赖固定文件名做外部脚本；请使用 `/api/report?id=` 与 `/api/download?id=`。
- 生产部署后可通过 `GET /api/health` 确认 `version=1.7.0`。
