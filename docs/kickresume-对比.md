# kickresume.com 与「简历评审助手」对比

> 调研时间：2026-10-22｜对标对象：kickresume.com（公开页面 + 第三方评测）｜本方依据：`prd.md` + 当前代码与实测
> 结论先行：**两者不是同一类产品**。Kickresume 是"简历生产线"，我们是"简历体检科"。它解决"没有简历 / 简历不好看"，我们解决"这句话会不会让我被筛掉"。

---

## 一、定位差异：一个在生产，一个在诊断

| 维度 | Kickresume | 简历评审助手 |
|---|---|---|
| 一句话 | AI 建站式简历/求职信生成器 | 上传现有简历，出一页能改的判断 |
| 核心动作 | 写 → 套模板 → 导出 → 投 | 读 → 判断 → 给可替换写法 |
| 隐含假设 | 你的问题是**不够优化**（缺关键词、排版不专业） | 你的问题是**没证据**（写了但证明不了） |
| 判据形态 | 一个百分制 ATS 分数 + 三条 strong/weak 点评 | 分数 + 档位 + 两道闸门 + 逐条引用原文 |
| 产出物 | PDF / DOCX / 个人网站 | Markdown 报告（复制即用） |
| 边界 | 停在"文档"，不负责投递 | 停在"判断"，不负责改稿 |

**关键差异在判据来源**：Kickresume 的分数来自"与库里成功简历的相似度 + 20 多项结构检查"，本质是**优化器**——分数低，它告诉你"再加点关键词、换个模板"。我们的分数来自"每条结论必须能逐字回指原文"，本质是**诊断器**——它告诉你"这句话没有可验证的结果，HR 会当成形容词"。

## 三、他们真正领先的地方（不是"功能多"，是结构性优势）

1. **闭环长度**：写、改、导出、投（部分）、跟踪，五步里有四步在他们产品内完成。用户改完我们的报告，还得回 Word 手动贴——**最后 1 公里断在我们这边**。
2. **模板即排版能力**：他们不用"检查排版"，因为模板保证不跑版。我们只能指出"留白太密 / 超一页"，给不出改好的文件。
3. **JD 级定制**：`Resume Tailoring` 把简历对着 JD 重写，这是"投 100 家"场景的刚需；我们连 JD 输入框都没有。
4. **账号与多端**：简历是"一季改一次"的资产，他们让资产可积累、可跨设备；我们每次从零开始。
5. **工程与合规背书**：8M 用户量级、GDPR、渗透测试、Trustpilot 可查。我们是 `http.server` 单机、无鉴权、无并发控制、无监控——自用够，给别人用不够。

## 四、我们真正领先的地方（可验证，不是自我安慰）

1. **每条结论都可回指原文**：`check_output` 强制 evidence 在原文逐字命中（实测 197/197）。他们给的是"内容偏弱"这种无法反驳也无从修改的判断。
2. **改写不许编数字**：改写里出现原文没有的数字，直接被撤出"三处可替换"区，并注明撤了几条。他们的一键 accept 没有这层闸门。
3. **客观性分级**：涉及学历/时间线的结论必须标 `inference` 并附"该问用户什么"。他们的 feedback 常出现"出生日期显得过时"这类越界判断。
4. **排版判断基于真实页面图**：10 项视觉检查（是否超页、留白密度、分区是否被切碎）。对"自己排版、投中文岗"的人，这比"换个模板"有用。
5. **明确的不知道**：不预测通过率、不给 offer 概率。他们的 ATS 分数容易被误读成"我能过"——而 ATS 只负责解析，真正筛人的是 HR 看 6 秒。
6. **隐私与成本**：本地跑、发模型前脱敏、无账号；一份 3.3k 输出 token，成本以分计。

## 五、差距分级：补什么，不补什么

| 优先级 | 缺口 | 判断 | 理由 |
|---|---|---|---|
| **P0 ✅ 已补** | JD 输入 + 关键词/证据覆盖表 | 补 | 已实现：贴 JD → 报告多「岗位匹配」段（覆盖 62%、哪些只堆砌、哪些缺失）。见 `CHANGELOG-v1.1.md` |
| **P0 ✅ 已补** | 改写成"可直接粘贴块" + 导出 .docx | 补 | 已实现：按原文顺序的可粘贴块 + `.docx` 导出（Word 可直接改） |
| **P1 谨慎** | 报告分享（生成静态 HTML 快照链接） | 可做 | 服务 S3 同学互评；但一旦要链接就要托管，破坏"本地"卖点 |
| **P1 部分已补** | 历史记录 / 版本对比 | 缓 | 已补最轻一层：只存分数，算「比上次 +N」；版本 diff 仍不做 |
| **P2 别补** | 模板 / 在线编辑器 / 代写正文 | 不补 | 就是另一个产品，且与"只做判断"的定位冲突 |
| **P2 别补** | 通过率预测 / 图表化分数 | 不补 | 无法预测，给数字就是编造 |

## 六、如果只做三件事

1. **加 JD 输入**：现成的 `case["jd"]` 字段一直是空的。填上后让模型输出"JD 要求 → 简历里的对应证据 → 缺什么"，这才是 Kickresume 的 Tailoring 无法替代的部分（他们补关键词，我们指出没证据）。
2. **把 3 条改写拼成"可粘贴块"**：按简历段落顺序输出，用户一次性粘回 Word，不用逐条找位置。
3. **给报告一个"改完再评一次"的入口**：同一份简历第二次上传时提示"上次 62 分，这次 71 分，进步在哪"。这需要最轻量的本地历史（一个 `reports/.index.json` 即可，不用账号）。
