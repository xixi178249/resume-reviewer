# 优化规划：借鉴 resume-expert 的六条改造（v2.3 起）

> 依据：`docs/对比-resume-expert.md`（154 行，逐文件读对方 5,504 行 md 得出）
> 原则：**只抄「知识广度」，不抄「无测量的自信」**。我们的主线是可信度（rubric 单一真源 + 453 条断言 + 盲评门槛），任何改造不得削弱它。
> 现状基线：23 套件 / 453 条断言全绿；提交 `960777c`。

---

## 0. 一句话取舍

对方强在**知道得多**（15 行业权重、低信息策略、本地化 ATS、透明 md）。
我们强在**证明得了**（阈值单一真源、写入前守卫、版本链、闭环度量）。

所以本轮优化的目标不是「变成他们」，而是：**把他们知道而我们不知道的行业知识，塞进我们已经可信的框架里。**

---

## 1. 六条方向（按优先级）

### D1 · 行业权重映射（P0，最值钱）

**问题（实测）**
- `scripts/rubric.py:194 weights()` 返回唯一一套权重；`scripts/check_output.py:31 WEIGHTS = rubric.weights()` 是**模块级常量**，整个进程只有一把尺。
- `grep -rn "industry" scripts/ web/ prompts/` → **0 命中**，行业概念完全不存在。
- 后果：投国企与投互联网拿同一标准；且 `DISCRIMINATORY` 正则会「中共党员」标成歧视性信息——不歧视做对了，「该行业看重什么」做少了。

**抄什么**：对方 `references/scoring-system.md` 的 15 行业 × 4 维权重表（我们 5 维，需重排）。

**改哪里**

| 文件 | 改动 |
|---|---|
| `config/rubric.yaml` | 新增 `industries:` 段：`default` + 10 个行业键（互联网/科技、金融/银行、国企/体制内、设计/创意、产品/运营、教育/培训、医疗/医药、游戏、零售/电商、政府/非营利），每个 5 维权重合计 100 + `emphasis:` 一句话 |
| `scripts/rubric.py` | 新增 `weights_for(industry=None)` / `industry_profile(industry)` / `list_industries()`；`weights()` 保留为 `weights_for(None)` 别名（不破坏 453 条现有断言） |
| `scripts/check_output.py` | `WEIGHTS` 常量改为评分函数内 `weights_for(report.get("industry"))`（签名加 `industry` 参数，默认 None） |
| `scripts/chat_engine.py:77` | 同样传 industry |
| JSON Schema | 新增可选 `industry`（枚举，可空） |
| `web/index.html` | 岗位输入旁加「行业」下拉，默认「通用（不指定）」 |
| 报告页 | 显示「按 XX 行业权重」+ `emphasis` 一句话 |

**验收标准**
1. 每个行业权重合计 = 100（测试断言）
2. `weights_for("金融/银行")["role_fit"] == 35`（抽样断言）
3. 未知行业 → 回落 `default` 且不抛异常
4. 同一份输出在 `default` 与「设计/创意」下总分不同，且差异**只来自权重**（维度分不变）
5. 453 条现有断言全绿
6. 新增断言 ≥ 15

**成本**：中（约 1 天）｜**风险**：行业枚举与用户认知不匹配 → 允许留空，留空即通用，不做强制选择。

### D2 · 分数段锚点细化 + 档位一致性校验（P1）

**问题**：现在只有 `verdict.strong_pass_min: 80 / pass_min: 65 / borderline_min: 50` 三个数字，prompt 里靠一句「为什么不是 64 也不是 75」撑着。对方是 5 档 + 每档典型特征描述。

**改**
- `prompts/system-v1.8.md` 评分锚点段：4 档 → 每档写「典型特征」（≥80：四维无明显短板、有可追问钩子；65-79：1-2 维中等短板；50-64：多项明显问题、建议结构级调整；<50：缺关键信息或内容撑不住门槛）
- **锚点表格从 `rubric.yaml` 生成**，不手写（防漂移）
- `check_output.py` 加软校验 `verdict_dim_mismatch`：verdict 为 strong_pass 但任一维 <3 → 打警告标记

**验收**：4 档特征齐全；新增 3 条断言（含「锚点数字 == rubric 阈值」）；报告出现不一致时前端显示提示。

**成本**：低｜**风险**：无（纯文本 + 软校验）

---

### D3 · 面试追问升级（P1，用户感知最强）

**问题**：`followup_risks` 是 3 条字符串，只有「可能被追问的点」，没有「会怎么问 / 该准备什么 / 常见翻车」。

**改**
- Schema：`followup_risks: [str]` → `[{point, likely_question, prepare, pitfall}]`，仍限 3 条
- prompt：对应改写，要求 `likely_question` 用面试官口吻
- `check_output.py`：四字段非空；**`likely_question` 里出现的数字必须在原文里**（复用 `number_audit` 思路，防追问编造）
- 报告渲染：四段折叠卡片

**验收**：schema 校验通过；新增 4 条断言（含「追问里的数字不在原文 → 报 `question_fabricated_number`」）；旧格式报告向下兼容（字符串自动转成 `{point: s}`）。

**成本**：中｜**风险**：schema 破坏性变更 → 用向下兼容读取，不强制迁移历史报告。

---

### D4 · 低信息简历：不硬拒（P2）

**问题**：`ingest.min_text_chars: 120`，低于直接拒（`CHAT_NO_TEXT`）。中间态（40-120 字：只有姓名+学校+一段实习）没有任何策略。

**改**
- `<40` 字 → 仍拒（确实是空）
- `40~120` 字 → **结构建议模式**：不给总分（复用已有 `insufficient_data`），给 3 条结构建议 + 缺失信息清单（联系方式/项目/量化/技能）
- 抄对方「技能概要补偿 + 排版补偿」话术

**验收**：40 字输入返回 `mode="advisory"`、无 `score`、有 3 条建议；新增 2 条断言。

**成本**：中｜**风险**：用户误把建议当评分 → 界面必须显著标注「信息不足，未评分」。

---

### D5 · 本地化 ATS 清单扩充（P2）

**问题**：`ats_check` 现有 10 项视觉白名单 + 4 项文本层，缺「平台怎么解析」。

**改**：新增 8 条平台解析层规则（表格嵌套表格、文本框内文字、联系方式放页眉页脚、图片化文字、英文缩写无中文全称、日期格式不统一、扫描版 PDF、多栏排版），报告里按「会被哪个平台漏读」分组（北森/Moka/通用）。

**验收**：8 条规则 + 8 条断言；报告分组渲染。

**成本**：中｜**风险**：平台行为会变 → 文案标注「截至 2026-11 的公开资料」，不做绝对断言。

---

### D6 · 规则透明化（P2，便宜的快赢）

**问题**：规则一半在 `rubric.yaml`（可读），一半在 1,200 行 `check_output.py`（只有开发者读得懂）。对方全是 md，用户能审阅。

**改**：写 `scripts/gen_rules_doc.py`，从 `rubric.yaml` + `check_output` 常量生成 `docs/评分规则.md`（人读表格）；加一条测试：**文档里每个数字必须能在 rubric 找到同值**，否则 FAIL。

**验收**：生成脚本 + 一致性测试 + README 链接；改 rubric 后忘记重新生成 → 测试报错。

**成本**：低｜**风险**：无

## 2. 实施顺序（三个批次，每批独立提交可回滚）

| 批次 | 内容 | 为什么这个顺序 | 预计 |
|---|---|---|---|
| **批次 1** | D1 行业权重 | 补最大结构性短板，机制已就绪，不需要新数据 | 1 天 |
| **批次 2** | D2 + D6 | 都只动文本/文档层，风险最低，且 D6 让 D1 的权重表可被人审阅 | 半天 |
| **批次 3** | D3 + D4 + D5 | 都动 schema/交互，放最后，一次只改一类 | 1.5 天 |

每批完成后：`python scripts/run_tests.py` 全绿 + 提交 + 更新 CHANGELOG。

## 3. 明确不抄的四条

| 不抄 | 理由 |
|---|---|
| 从零生成简历（模式 A） | 与「零编造」卖点直接冲突；且会把改稿变成重新排版 |
| docx / LaTeX 输出链 | 改的是句子，排版交给用户自己的模板；引入生成会把「改哪句」变成「重排一份」 |
| 75 份手写 golden 的 ±5 允差 | 我们的双人盲评 + κ≥0.6 + MAE≤8 更硬；手写 golden 容易自证（分数照规则反推） |
| 向量库 / RAG 检索知识库 | 5504 行 md 是他们的资产，不是我们的问题；我们缺的是行业权重，不是检索能力 |
