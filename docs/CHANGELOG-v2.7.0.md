# v2.7.0：给项目装一把自己的尺子

一句话：新增 `skills/project-eval/` —— 一个能给别人（也能给自己）打分的项目测评技能，
七维评分卡，每个数字都能追到一条命令；测不出来的写「判不出」，不拿 0 分充数。

## 为什么要做这个

上一版的自评（`docs/自评-v2.5.md`）是手工写的：翻文件、数断言、贴截图、凭印象给「功能完整度 9.2 / 可信度 6.5」。
手工自评有三个问题：

1. **不可复现**：下个月再让我评一次，数字会变，但没人知道是项目变了还是我记错了。
2. **不可比较**：和竞品对比时，「9.2 分」这个数字没有口径，对方也没法用同一把尺子量。
3. **容易自我美化**：没有约束的评分，最后都会滑向「整体完成度较高」。

所以把它写成脚本：跑真命令、收真数字、按固定公式算分。要改口径，就得改代码 + 改
`references/评分口径.md`，而且有测试盯着两边不许漂。

## 七个维度

| 维度 | 权重 | 靠什么测 |
|---|---|---|
| 可验证性 | 25% | `scripts/run_tests.py`：套件数、断言数、是否全绿 |
| 端到端可用 | 20% | `scripts/selfcheck.py`：探针通过率与 FAIL 明细 |
| 线上可用 | 15% | `/api/health` 版本 + `/`、`/rules`、`/chat` 状态码 |
| 文档一致 | 10% | VERSION / package.json / README 头部 / CHANGELOG / 相对链接 |
| 代码卫生 | 10% | 三层依赖、静默吞异常、最大单文件 |
| 交付完整 | 10% | CHANGELOG、截图、分发包、规则页 |
| 评测资产 | 10% | 金标样本、留出集、bench 状态、局限清单 |

## 三条设计取舍

**一、「判不出」不进分母。** 没连上线上就把权重按剩余维度归一，而不是记 0 分。
理由是「今天网不好」和「线上挂了」是两件事，混在一起会让报告失去诊断价值。
报告顶部会明写排除了哪几项，读者自己判断要不要补测。

**二、依赖分三层。** 顶层 import（装不上就跑不起来）扣分；函数内 import（只有那条链路需要）
只记录；`try: ... except ImportError` 里的（没有也能跑）只记录。第一版按正则一刀切，
把 PDF/DOCX 解析用的四个库全算成硬依赖，一个零第三方依赖的 Web 服务被打成代码卫生 **0.0** ——
这个错判比不测更糟，因为它看起来非常「有依据」。

**三、单独留一维给评测资产。** 588 条断言全绿、线上零故障，同时只有 8 份人工金标、留出集 0 份 ——
这两件事都是真的，但只有前者能写成「做完了」。这一维低于 5 分，报告解读必须降一档，
否则就是在用工程分替可信度背书。

## 顺带抓到一个真 bug

第一次跑全量自评，`F13.4`（「自己改这一版」：存成 v2 并当场报分差）从 PASS 变成 FAIL。
查下来是自评脚本自己的锅：版本链默认落在 `reports/versions/`，而探针用的是固定 GOOD 文本，
`doc_id` 是正文的 sha256 —— 上一轮留下的 v2 内容与这一轮要存的完全相同，
于是被 `CHAT_UNCHANGED` 正当地拒掉。

修法：自评起服务时把 `CHAT_STORE_DIR` 指到临时目录（`scripts/selfcheck.py`），
跑完自动删。修完 **40/40 PASS**。

这也是这个技能存在的意义：**探针不隔离这类问题，只有每天真跑一次才会露头。**

评测资产 5.0 因为金标只有 8 份、留出集 0 份、bench 仍是 PILOT。

## 没做的

- **没做 CI 门禁**：脚本退出码恒为 0，要当门禁得读 json 里的 `total`／`defects`，这一步留给你。
- **没做历史趋势**：只出当期快照，不存基线，所以「比上版退步了 0.3」这种话现在还说不出来。
- **没测并发与成本**：没有压测与账单数据，多用户下的延迟、限流、开销都不在卡里。
