# resume-reviewer 2.0.0 发布说明

> **一句话：2.0 换的不是模型，是「凭什么相信这个分数」。**
> 规则一条没改（评分口径仍是 v1.8），改的是它周围那圈东西：阈值有了唯一真源、能一键出基准报告、
> 能发盲评稿请人打分、能算人与人之间的一致性、能看每一份改写到底被用上了没有、
> 能告诉用户「这个分数现在可不可信」。

## 1. 这一版到底加了什么

| 能力 | 用户能看到的变化 | 入口 |
|---|---|---|
| 评分规范单一真源 | 改阈值只需改 `config/rubric.yaml`，代码/prompt/schema 三处由测试钉住不许漂 | `scripts/rubric.py`、`scripts/test_rubric_single_source.py` |
| 一键基准报告 | 一条命令出 MAE / κ / QWK / ±5 / ±10 与「是否达门槛」；数据不够就明写 NOT_READY | `scripts/benchmark.py` |
| 数据集扩建护栏 | 按正文去重、同来源组不跨切分、已标注样本切分冻结 | `scripts/dataset_build.py` |
| 双人盲评发稿 | 一条命令生成只含正文+盲号的手读稿（不含模型分数），两人顺序不同 | `human_eval.py blind` |
| 分歧仲裁清单 | 分差 > 阈值的样本单列，并指出「差在哪几个维度」 | `human_eval.py arbitration` |
| 独立标注者上手材料 | 五维 1/3/5 锚点与反例、两道关 if-then、五个「不要」 | `docs/盲评锚点卡.md` |
| 改稿闭环落实率 | 报告里能看出「我给的改写，用户到底用没用上」 | `scripts/closure.py` + `/api/metrics` |
| 可信度横幅 | 页首一条横幅：未验证时如实写「样本 8/60、标注者 0/2」，报告首屏也带一行 | `web/index.html`、`GET /api/metrics` |
| 四阶段进度 | 等 30 秒时能看到「脱敏 → 读格式 → 逐项检验 → 出报告」 | `POST /api/review/start` + SSE |
| 留存策略开关 | 公网部署可声明「评完即删」；本机保留历史 | `RETENTION=ephemeral` |

## 2. 必须一起读的一段话（别只看版本号变大）

**这仍然是「未验证」的状态。** 具体数字：

- 数据集 **8 / 60** 份，留出集 **0 / 18** 份；
- 独立标注者 **0 / 2** 人，人工标注 **0 / 60** 份；
- 因此：`benchmark.py` 必然输出 `NOT_READY`，报告页顶部的可信度条是琥珀色「未验证」，
  任何「准确率 85%」「和 HR 一致」这类说法**都不许出现**；
- 唯一可以引用的旧数字是「4 份单人非盲样本上 MAE=8.0」，它是探索性代理，
  且权重是先看过这几份样本才定的，属自我实现，**不得当基准继承**。

2.0.0 的含义是：**测准它的工具链齐了**，而不是「它已经准了」。这也是为什么版本升到 2.0
却没有在页面上加任何「已验证」——那要等两份人工标注回来。

## 3. 从 1.10.1 到 2.0.0 的路径

| 版本 | 主题 | 关键点 |
|---|---|---|
| 1.11.0 | 可信度进产品 | 横幅 + 报告行 + `/api/metrics`；未就绪时指标为 `null` 而非 0 |
| 1.12.0 | 改稿闭环落实率 | 落盘 `.meta.json`，前后两版对比；规则引擎占位改写不计入 |
| 1.13.0 | 留存策略 | 公网默认「评完即删」并明说，不假装有持久盘 |
| 1.14.x | 流式与观测 | SSE 四阶段 + `stage_ms`/tokens + 请求分位数 |
| 1.15.0 | 盲评发稿与仲裁 | 稿子里没有模型分数，两人顺序不同，分歧按维度定位 |
| 1.16.0 | 锚点卡 | 稿子自带 1/3/5 锚点；否则 κ 量的是各自的标准 |

## 4. 验收怎么自查（不花钱）

```powershell
cd resume-reviewer
python scripts/run_tests.py                 # 20 套件 374 断言，约 13 秒，不联网
python scripts/qa_smoke.py                  # 55 项真实 HTTP 冒烟（需本地 server 在跑）
python scripts/benchmark.py                 # 必然 NOT_READY，这是对的
python scripts/human_eval.py blind --reviewer R01 --out samples/eval/handouts
```

## 5. 2.0 之后真正剩下的活（只有人能做的）

1. **攒到 60 份简历**（其中 18 份 heldout）：丢进 `samples/raw/` → `dataset_build.py --source samples/raw` → `--verify`；
2. **找 2 名独立标注者**：把 `samples/eval/handouts/` 里的稿子发给他们 + `docs/盲评锚点卡.md`；
3. 两人填完 → `human_eval.py arbitration` 看分歧 → `report` 出一致性；
4. 数据齐了 → `benchmark.py` 变 `READY` → 页首横幅自动转绿，届时才允许对外说准确率。
