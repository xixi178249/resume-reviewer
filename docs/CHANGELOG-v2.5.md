# v2.5.0（2026-11-06）— 招聘系统（ATS）能不能读出来

## 一句话

报告多一节「招聘系统能不能读出来」：**同一份简历投北森、Moka、智联、前程无忧、实习僧、猎聘、Workday，
各自会被怎么看**——能判的当场判，判不出的老实写「判不出」，不许猜。

## 改之前是什么样

报告只有两层格式检查：

1. **文本层**（`format_review.text_level`）：章节在不在、联系方式提不提取得到、乱码几个、估算几页；
2. **视觉层**（`format_review.visual_level`）：10 项，靠截图判图片化文字、分栏、字号。

这两层都是「这份文件本身好不好读」。缺的是第三层：**投到哪个平台、那个平台在意什么**。
用户拿到 82 分、格式也 clean，照样可能因为「没有起止年月」在北森里被并成一段、
因为「自我评价里才写岗位词」在 Moka 里搜不到。这些不是打分问题，是平台差异问题。

## 改之后

报告新增一节（位置在「排版上要改的地方」之后、建议改写之前）：

```
## 招聘系统（ATS）能不能读出来

系统先读一遍，人再读一遍。下面按平台列它在意什么：✓ 16 条已满足、✗ 1 条没满足、? 7 条要你自己核。

### 北森（校招/国企主流）
> 先解析成字段再人工筛，段落缺起止年月会被并成一段
- ✓ 已满足：每段经历都写起止年月（2024.09—2025.06），别只写「2024」
- ? 判不出：单栏排版，不用表格分栏　——　版面（分栏、表格、页眉页脚）在正文里看不到…
```

七个平台，检查项全部来自 `config/rubric.yaml` 的 `ats.platforms`：

| 平台 | 它怎么看 | 检查项 |
|---|---|---|
| `beisen` 北森（校招/国企主流） | 先解析成字段再人工筛，段落缺起止年月会被并成一段 | 4 条 |
| `moka` Moka（互联网/中型公司主流） | 强依赖标准章节名分组，自定义标题会掉进「其他」 | 4 条 |
| `zhaopin` 智联招聘 | 平台内是表单字段，上传附件只作补充，筛选看表单 | 3 条 |
| `job51` 前程无忧 | 以关键词检索为主，附件解析容错低 | 3 条 |
| `shixiseng` 实习僧 / 牛客 | 学生简历为主，附件 PDF 直接看，关键词命中影响推荐 | 3 条 |
| `liepin` 猎聘 | 中高端岗位为主，经历连续性看得比关键词重 | 3 条 |
| `workday` Workday / Greenhouse（海外投递） | 强结构化录入：日期格式、单栏、无页眉页脚 | 4 条 |

三种状态，只有这三种：

- `✓ 已满足` —— 从正文就能确认（有起止年月、有手机号、有标准章节名、岗位词在正文里、估算一页内）；
- `✗ 没满足` —— 同上，但确认是缺的，附一句「为什么会吃亏」；
- `? 判不出` —— 正文里根本没有这个信息（版面、平台表单、文件名），**既不算通过，也不算不合格**。

## 五条设计取舍

1. **判不出就 `unknown`，不猜。**
   版面、平台表单、文件名这七条永远 `unknown`。给它们打「已通过」是假安心，打「没通过」是假警报。
   测试 `test_layout_form_filename_are_always_unknown` 钉死这一点。

2. **只从正文判五类。**
   `dates_/sections_/contact_/keywords_/length_` 能从字里看出来，就判；
   其它前缀（`layout_/form_/filename_`）一律 `unknown`。
   没有「看一眼猜一下」的中间地带。

3. **不写「会被自动淘汰」。**
   平台规则会变，我们也没有任何平台的官方解析器。报告里那句
   「这些是公开信息与实测经验的总结，**不是任何平台的官方文档**；以投递页面的预览为准」
   是固定的，测试会检查它还在（`test_no_doom_claims` 会拦「自动淘汰」「百分之百」这类词）。

4. **探针前缀强制校验。**
   `checks` 的 key 必须形如 `dates_range` / `sections_std`，前缀不认识就抛 `RubricError`。
   理由：写了条目却没人判，等于给用户一句假的「已检查」。加了条目就逼着补判定，或者删掉。

5. **视觉 10 项与致命 5 项搬到配置里。**
   v2.4.1 之前这 10 项在 `check_output.py` 硬编码一遍、`prompts/system-v1.8.md` 又抄一遍。
   改一处漏一处，就出现「脚本判 10 项、prompt 让模型判 8 项」。现在只有 `rubric.yaml` 一份，
   `check_output` 从它读，`test_ats_platform.py` 断言 prompt 的 1.2 表格与它**逐字一致**。

## 数字

- 测试：**27 个套件 / 562 条断言**（v2.4.1 是 26 / 542，新增 `ats` 套件 20 条）。
- `docs/评分规则.md`：144 行（v2.4.1 是 122 行），新增「9.2 平台层」整节，网页 `/rules` 同步可看。
- 真机验收（本地规则引擎 + 真浏览器）：报告出现该 h2、7 个平台 h3、23 个节点，
  页面无字面 `###` 残留；同一份简历两项判定不同（`workday` 的 `dates_fmt` 判「没满足」，
  因为它要 `MM/YYYY` 而正文写的是 `2024.09—2025.06`）——这正是这一节的价值：**不同平台要求不一样**。

## 没做的三件（想清楚了才不做）

1. **不做「平台打分 / 模拟解析」。** 我们不是任何平台，也没有官方解析器。
   真去模拟，输出的每一条都是猜的，比不给更糟。
2. **不做「每个平台生成定制版简历」。** 七份定制版简历是七份要维护的事实，
   而用户真正需要的是「同一份简历里哪些写法各平台都吃亏」——那是检查清单能解决的。
3. **不把平台层写进 JSON Schema。** 它是从正文现算的（`scripts/ats_platform.py`），
   不依赖模型输出，因此不进契约、不会因为模型换版本而漂移。
