# 实习简历评审助手：第一步该做什么

> 结论先给：**第一步不是写代码、不是调模型，而是「定标准 + 攒评测集」。**
> 两个小时内可以做完，做完之后你后面每一次改 prompt 都有据可依。

---

## 为什么不是先写代码

做这类工具，效果的大头来自两件事：

1. **判断标准（rubric）** —— 什么叫"这份简历能过初筛"，要能量化到"哪一句话会让他挂"
2. **改写示范（few-shot / rewrite 样例）** —— 模型不会改，往往是因为它不知道"好句子长什么样"

这两件事都跟框架无关。你换成 LangChain、Dify、扣子、还是 200 行 Python 脚本，结果几乎一样。
反过来，如果标准是"建议加强量化描述"这种空话，你接十个大模型也只会得到十份礼貌的废话。

**而评测集是室友这个项目独有的、别人拿不到的资源**：你手里有 10 份真实简历，这正是最贵的东西。

## 两小时路线图

> 配套代码已在本目录，两条命令就能看到效果（不需要 API Key）：
>
> ```powershell
> cd resume-reviewer
> python scripts/run_eval.py --selftest   # 校验器能抓到"编造"吗 → 4 项 PASS
> python scripts/run_eval.py --mock       # 全链路指标（固定剧本，不调模型）
> ```
>
> `--mock` 已验证输出：样本 3 份，引用命中率 1.0，编造数字 0，与人工分 MAE 2.3。
> 这只证明**管子通了**，不代表模型效果——效果要等你换 `--real` 用真实简历跑出来。

### 第 1 步（15 分钟）把三个问题写死

| 问题 | 不写清楚会发生什么 | 建议答案（针对你这个场景） |
|---|---|---|
| 谁用？ | 给社招/校招设计的标准，套在找第一份实习的本科生身上全是误伤 | 大二/大三，找**第一份**实习，多数没有正式实习经历 |
| 投什么岗？ | "通用简历评审"= 什么都评不准 | 先只做 1~2 个方向，比如后端开发 + 产品运营 |
| 什么叫评得好？ | 你会一直觉得"它说得挺对但没用" | **能指出哪句话会挂，并给出可直接替换的句子** |

第三行最重要。判断标准可以写成一句话：

> 好的评审 = 候选人看完 10 分钟内能改完 3 处，且改完自己知道为什么这么改。

### 第 2 步（30 分钟）收集 8~10 份真实简历 + 人工打分

- 找室友、舍友、同班同学要，**先脱敏**（手机号/邮箱/身份证，工具已附：`scripts/extract_text.py --desensitize`）
- 让他们自己先花 5 分钟打个分（0~100）+ 一句话："这份简历最想改的一句话是什么"
- 至少覆盖四种类型，否则评测没有区分度：
  - 全是"参与了 XX 开发"的空话型
  - 方向明显不对/经历太单薄的裸简历
  - 写得还不错的（**必须有**，用来测模型会不会对好简历也硬凑问题）
  - 格式崩坏、有错别字的硬伤型

### 第 3 步（30 分钟）把输出格式写死

不要自由文本。要求模型输出 JSON，**必须**包含两个字段：

- `evidence`：逐字摘自简历原文的片段 → 用来事后自动校验"它有没有瞎编"
- `rewrites`：把原句改成可替换的版本 → 用户真正会用的东西

本仓库已给：`prompts/output-schema-v0.1.json`

### 第 4 步（30 分钟）写 prompt v0.1 + 跑通评测

本仓库已给：`prompts/system-v0.1.md` + `scripts/run_eval.py`

```powershell
cd resume-reviewer
python scripts/run_eval.py --mock          # 不花一分钱，先确认链路通
```

依赖只有 `python-docx` 和 `pypdf`（本机已装）；`pdfplumber` 未装，仅作为 pypdf 提取空时的兜底，
真遇到扫描件再 `pip install pdfplumber`，或者手动复制文本。

### 第 5 步 看四个指标，而不是"感觉它答得好不好"

| 指标 | 健康值 | 说明了什么 |
|---|---|---|
| 分数与人工分差（MAE） | ≤ 10 | 模型的"严格程度"跟人一致吗 |
| `evidence` 原文命中率 | ≥ 95% | **它是不是在编造简历里没有的内容** |
| 改写中的凭空数字 | 0 | 最危险的一类错误，见下 |
| 同分不同 verdict / 权重不自洽 | 0 | 模型自己算不明白分，说明标准没被理解 |

## 三个一定会踩的坑（现在就可以预防）

1. **中央趋势**：模型给每份简历都打 68~75 分，因为这样"最不容易错"。
   → 解法：给每个维度写 1 分 / 3 分 / 5 分的**行为锚点**，并强制输出 `verdict`（过/悬/挂），逼它做取舍。

2. **只夸不改**：满屏"整体结构清晰，建议进一步突出亮点"。
   → 解法：`rewrites` 至少 2 条，且 `fix` 必须是"把 A 改成 B"的祈使句，禁止出现"建议加强""可以考虑"。

3. **编造数字**（这条会害到室友）：简历里写"参与了二手交易平台开发"，模型改写成"支撑日均 5000 单交易"。
   面试官一问就崩。
   → 解法：prompt 里禁止新增数字，缺的用 `[待补充：xxx]` 占位；
   **并且用脚本自动检测**改写里出现的数字是否在原简历中存在——这是本校验脚本里最有价值的一条检查。

---

## 隐私红线（别跳过）

- 真实简历里有手机号、姓名、学校、公司名。调用第三方 API 前先脱敏。
- 生成简历文本时默认开启 `--desensitize`；原始文件别往公开仓库推。
- 提前跟室友说清楚：文本会发到你选的大模型服务商。有人介意就别用他的简历。

## 第一步做完之后（第二步再看）

1. 攒到 20 份标注样本后，做一次**校准**：人工分 vs 模型分散点图，看是系统性偏高还是偏低，然后整体平移阈值。
2. 加一个"**补位建议**"模块：这个人群最大的痛点不是改，是**没东西可写**——课程项目、竞赛、开源、GitHub 怎么补成一段能看的经历。这是同类工具普遍缺失、也最容易做出差异化的点。
3. 产品形态：**先做命令行 / 单次对话**，别做前端。等你确认室友每周真的会用第二次，再考虑做网页。
