# 评分口径

这份文档是 `scripts/eval_project.py` 的唯一说明书。**代码改了这里必须跟着改**——
一张自己都在漂移的评分卡，没资格给别人打分。

总分 = Σ(维度得分 × 权重) ÷ Σ(参与加权的权重)，保留一位小数。
权重：可验证性 25 / 端到端 20 / 线上 15 / 文档 10 / 代码卫生 10 / 交付 10 / 评测资产 10 = 100。

档位：≥9.0 优秀、≥7.5 良好、≥6.0 合格、<6.0 待改。

**「判不出」的处理**：某维拿不到数据时该维不进分子也不进分母，权重按剩余维度归一，
报告顶部会明写排除了哪几项。这样「今天没网」不会被读成「线上挂了」。

## 一、可验证性（25%）

跑 `scripts/run_tests.py`，解析 `全部通过：N/N 个套件，M 条断言`。

| 断言数 | 基线 |
|---|---|
| ≥600 | 10 |
| 400–599 | 9 |
| 250–399 | 8 |
| 120–249 | 6 |
| 50–119 | 4 |
| <50 | 2 |

有任一套件失败时，得分 × 0.3——**红着的 500 条断言不如绿着的 50 条**。
项目里没有 `scripts/run_tests.py` 时判不出，不记 0。

## 二、端到端可用（20%）

跑 `scripts/selfcheck.py`（自己起服务、自己收场），解析 `共 N 条：PASS a / PARTIAL b / FAIL c`。

```
得分 = 10 × (a + 0.5b) / N − 0.5 × c
```

PARTIAL 算半分：它测到了但结果不完整，既不能算通过，也不该等同失败。

## 三、线上可用（15%）

打 `/api/health`（失败先重试 3 次，仍失败则退回 `curl -sk` 再试——本地代理常把
urllib 的 TLS 掐掉，那是环境问题不是线上问题），再打 `/`、`/rules`、`/chat`。

| 情况 | 得分 |
|---|---|
| 线上版本 == 仓库 `VERSION`，三个页面全 200 | 10 |
| 能连上，但版本落后一版 | 7 |
| 能连上，有页面非 200 | 4 |
| 能连上但读不到版本 | 6 |
| 完全连不上 | 判不出 |

没给 `--base` 时判不出，不记 0。

## 四、文档一致（10%）

从 10 起扣：

| 问题 | 扣分 |
|---|---|
| `VERSION` / `package.json` / `package-lock.json` 版本不一致 | −3 |
| `README.md` 前 40 行没写当前版本 | −2 |
| 缺 `docs/CHANGELOG-v{版本}.md` | −3 |
| 相对链接指向不存在的文件 | 每条 −1，最多 −4 |

只查相对链接：`http(s)://`、`mailto:`、`#锚点` 一律跳过（外链能不能打开不是这个技能的事）。

## 五、代码卫生（10%）

从 10 起扣：

| 问题 | 扣分 |
|---|---|
| 顶层第三方依赖 | 每个 −2，最多 −6 |
| 静默吞异常（`except ...: pass/continue`） | 每处 −0.5，最多 −3 |
| 最大单文件 > 2500 行 | −1 |

依赖分三层，只有**顶层**扣分：

- **顶层**：模块加载即需要，装不上就跑不起来 → 扣分
- **函数内**：只有那条链路需要（如 `import pdfplumber` 写在 `extract_pdf()` 里）→ 只记录
- **`try` 内**：`except ImportError` 兜住了，没有它也能跑 → 只记录

这一条是踩出来的：早先按正则一刀切，把 PDF/DOCX 解析用的四个库全算成硬依赖，
一个零第三方依赖的 Web 服务被打成代码卫生 0.0。

## 六、交付完整（10%）

四项相加，上限 10：

| 项 | 分 |
|---|---|
| 有 CHANGELOG | 4 |
| 有截图（`docs/screenshots/*.png`） | 2 |
| 有可分发包（`*.zip`） | 2 |
| 有规则页（`web/server.py` 里接 `rules_page`） | 2 |

## 七、评测资产（10%）

四项相加，上限 10：

| 项 | 分 |
|---|---|
| 金标样本 ≥50 | 4 |
| 金标样本 20–49 | 3 |
| 金标样本 8–19 | 2 |
| 金标样本 1–7 | 1 |
| 没有金标 | 0 |
| 留出集非空 | +2 |
| `bench/report.json` 的 readiness 为 READY | +2 |
| 同上为 PILOT（只够内部看） | +1 |
| 有写明「测不到什么」的文档（自评/局限/评测方案优先） | +2 |

金标样本数取 `*dataset*.json` 里 `samples` 数组长度（或顶层数组长度）的最大值；
文件名带 `held` 的算留出集。

**为什么单独设这一维**：工程分和可信度是两件事。一个项目可以 588 条断言全绿、
线上零故障，同时只有 8 份人工金标、留出集 0 份——那时候「它能跑」是真的，
「它判得准」还只是愿望。这一维低于 5 分，报告解读就要降一档。

## 缺陷分级

| 级别 | 什么时候给 |
|---|---|
| 高 | 测试套件失败、端到端 FAIL、金标 <20 份、留出集为 0 |
| 中 | 文档漂移、死链、静默吞异常、部署落后、bench 为 PILOT/NOT_READY |
| 低 | 第三方依赖、单文件过大 |

## 改口径的规矩

1. 先改代码，再改这份文档，同一次提交。
2. 权重合计必须仍是 100，改完跑一次 `eval_project.py` 自检。
3. 新加的维度必须有「判不出」分支，否则遇到缺数据必然误判。
