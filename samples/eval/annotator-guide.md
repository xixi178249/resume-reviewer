# 独立标注者说明（评分轮）

> 你参与的是一个简历修改助手的质量评估。第一轮只评简历本身，**不要打开任何模型报告、演示页面、项目文档或另一位标注者的结果**。

## 你会拿到什么

- 一份脱敏简历正文（以 `blind_id` 命名）；
- 目标岗位与 JD（可为空）；
- 一个 `独立标注-<你的编号>.json` 文件。

不要尝试搜索简历中的姓名或学校，不要联系简历本人。不要把简历正文、证据片段或标注结果发到公开群聊、网盘或第三方工具。

## 你怎么评

先完整读一遍，再按顺序完成每个样本：

1. 给五个维度打 1～5 分（只能整数）；
2. 选一个总档位；
3. 判断两关是否通过；
4. 给自己的判断置信度 1～5；
5. 可选：写 0～5 条最关键的问题，证据从原文逐字摘录，最多 120 字。

不要参考“别人可能怎么评”，按你实际招实习生时的判断。

### 总分怎么来

你不需要另外拍一个 0～100 分，程序按固定权重算：

```
总分 = round((role_fit×0.25 + impact×0.25 + evidence_quality×0.20
             + structure×0.15 + competitiveness×0.15) × 20)
```

### 五个维度

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| `role_fit` 岗位匹配 | 基本不对口 | 部分技能/经历相关 | 经历直接对应岗位核心职责 |
| `impact` 结果与影响 | 只有职责描述 | 有结果但口径/归因不完整 | 动作、结果、规模可核验 |
| `evidence_quality` 证据质量 | 无法追问出真实贡献 | 有部分证据但链不完整 | 方法、边界、个人贡献都有证据 |
| `structure` 结构与可读性 | 找不到重点或严重排版问题 | 基本可读但层次一般 | 3 秒能抓到主线，排版稳定 |
| `competitiveness` 竞争力 | 明显低于同岗竞争者 | 达到门槛但无差异点 | 有稀缺证据/深度项目 |

`structure` 只看你可以看到的文本；没有页面截图时，不要猜字体、分栏、留白。

### 总档位

- `strong_pass`：明显强于同岗竞争者，愿意优先推进；
- `pass`：达到投递门槛，可以进入下一轮；
- `borderline`：有亮点但风险明显，需要看岗位/名额；
- `reject`：按这个岗位目前不建议投。

### 两关

- `gate_hr`：15～30 秒初筛，你是否愿意留下这份简历；
- `gate_interview`：作为业务面试官，你是否认可这段经历、愿意进入面试。

两关独立判断，不必和总档位完全一致。

### 问题条目（可选）

只写最关键的 0～5 条：

```json
{
  "dimension": "impact",
  "evidence": "从简历逐字摘录的原文片段",
  "severity": "high",
  "comment": "为什么这是问题，最多 200 字"
}
```

不要复制整段简历，不要写手机号、邮箱、身份证等敏感信息。

## JSON 填写示例

```json
{
  "blind_id": "ANON-7QK2",
  "job_target": "后端开发实习生（Java）",
  "jd": "",
  "dimensions": {
    "role_fit": 4,
    "impact": 2,
    "evidence_quality": 2,
    "structure": 3,
    "competitiveness": 2
  },
  "verdict": "borderline",
  "gate_hr": true,
  "gate_interview": false,
  "confidence": 4,
  "issues": [],
  "notes": ""
}
```

## 提交前检查

- 每个样本五个维度都是 1～5 的整数；
- 每个样本都有档位、两关、置信度；
- 没有把未完成的样本交出去；
- `completed_at` 填实际完成日期；
- `blind_to_model` 保持 `true`；
- 没有看模型结果，也没有和另一位标注者讨论具体样本。

有不确定的地方，记录在 `notes`，不要猜成确定事实。
